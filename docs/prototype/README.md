# Интерактивный прототип Telegram-бота

[tennis-flow.html](tennis-flow.html) — автономный фрагмент интерфейса с локальной
моделью тестовых данных. Его можно открыть как HTML в браузере или встроить в
оболочку просмотра. В разговоре показывается тот же фрагмент; копия в Git нужна
для совместного обновления с кодом и документацией.

[finance-proposal.html](finance-proposal.html) — согласованный финансовый макет
от 7 октября. В нём «Перевести», собственный перевод, общая история «Мои / Все»,
балансы по 15 с профилем и выбором перевода, единая карточка суммы, отмена
ожидания отправителем и административные правки. Данные вымышленные;
макет не отправляет деньги и запросы в Telegram. Состояние установки кода
указано в [DEPLOYMENT_STATUS.md](../DEPLOYMENT_STATUS.md).

## Что можно пройти

- Три роли, две изолированные группы, личный и общий чат.
- Создание тренировки любым участником, последовательные название / дата / время,
  выбор группы, проверка перед публикацией, возвраты и непосредственная отмена.
- Присоединение с 0 ч, полная таблица, несколько гостей, время ±0,5/±1 ч,
  оплата ±5/±50/±100 ₽; «Не участвую» удаляет участника, оплату и гостей.
- Учёт создателем или администратором; учтённая тренировка не появляется у автора
  только из-за авторства. Участие и оплата остаются самостоятельными основаниями.
- Немедленное добавление и исключение игроков, управление их участием обычными
  кнопками, изменение деталей и четыре разрешённых перехода статуса.
- Мои финансы после выбора группы: отправка по предложениям, принятие только
  получателем, ожидание без проводок и повторных предложений, история и баланс группы.
  Имена в балансе группы открывают демонстрационный профиль, как в таблице тренировки.
  Старые формы переводов удалены из макета; отменённый перевод остаётся виден
  в нынешней истории и деталях без возможности повторной записи.
  Списки отправки / принятия — по три, история — по пять, баланс группы — по десять строк.
- Список ролей, назначение и снятие администраторов только суперадминистратором.

Модель повторяет основные правила распределения по игровому времени и отдельным
гостевым местам. Это не замена тестам расчётного ядра: ошибки сети, параллельная
правка с другого устройства и реальные разрешения Telegram здесь не воспроизводятся.
Добавление игрока отмечает участие с 0 ч, как выполняет SettlementService.

## Проверка и обновление

Проверено нажатием кнопок в браузере: создание без участия, учёт и фильтр автора,
новые шаги оплаты, гости и выход, правка состава, переводы, назначения, возвраты
и несохранённый ввод. Также пройдены ожидание / принятие платежа, отмена и восстановление тренировки,
27 строк без страниц, тёмная тема и изоляция второй группы; ошибок JavaScript нет.
Дополнительные сценарии описаны в
[UI_REGRESSION_SCENARIOS.md](../UI_REGRESSION_SCENARIOS.md).

При изменении бота прототип **не обновляется автоматически**. В том же наборе
правок нужно сверить подписи и переходы в Screens, права и команды в
SettlementService / SelfServiceBot, обновить прототип и
[схемы по ролям](../diagrams/README.md). Не считать успешные проверки Kotlin
проверкой этого отдельного JavaScript-прототипа.

Для повторной браузерной проверки подготовить оболочку и запустить сценарии
в окружении с установленным Playwright и его Chromium:

```sh
python3 docs/prototype/render-preview.py /tmp/tennis-prototype.html
node docs/prototype/check.cjs /tmp/tennis-prototype.html
node docs/prototype/check-extra.cjs /tmp/tennis-prototype.html
node docs/prototype/check-finance.cjs /tmp/tennis-prototype.html
node docs/prototype/check-calendar.cjs /tmp/tennis-prototype.html
node docs/prototype/check-training-states.cjs /tmp/tennis-prototype.html
node docs/prototype/check-personal-flow.cjs /tmp/tennis-prototype.html
```

Вместо Chromium Playwright можно задать путь к локальному Chrome через `CHROME_BIN`.
Тесты используют отдельный временный профиль, не входя в настоящие аккаунты.

В форме создания добавлены стрелки даты и две колонки начала — часы / минуты.
Стрелки над и под значениями меняют часы на 1, минуты на 30; числа не меняют ввод.
В личных настройках — название и время начала новых тренировок пользователя,
по умолчанию18:30. Учёт и отмена меняют состояние закрепа; восстановление не закрепляет
автоматически. Одна текущая панель макета соответствует новому правилу личного меню.

Назначения доступны суперадминистратору по пути «Настройки» → «Настройки групп» → выбор группы →
«Администраторы группы», с возвратом в настройки выбранной группы.

Общая карточка содержит одну кнопку «Открыть» в одной строке. «Редактировать»
доступно создателю и администратору в основной персональной панели; в подменю
времени / оплаты и управлении игроком этой кнопки нет. Для учтённых и отменённых
тренировок «Открыть» и старые кнопки участия показывают окно с «ОК» для любой роли.
Только три статуса: Открыта, Учтена, Отменена. «Открыть заново» сразу снимает расчёт;
повторный учёт применяет новый. Нейтральная подпись о балансе этой тренировки убрана.

Открытая карточка заканчивается таблицей: пояснение о предварительном расчёте убрано.

Создание завершается выбором группы; назад и отмена стоят в одной строке,
отмена создания сразу возвращает в главное меню. Настройки тренировки принадлежат
выбранному пользователю. «Мои тренировки» объединяют обе демонстрационные группы,
показывают общую статистику и восемь записей на страницу. Карточка просмотра отделена
от редактора. В сообщениях нет названия группы и пояснения об отменённой тренировке.

Редактор обновлён: отдельное меню статусов с четырьмя переходами, немедленное
добавление и исключение, управление от имени игрока обычными кнопками участия.
При входе из общей карточки нет кнопки «Назад»; из личного списка возврат сохранён.
Прошлая форма игрока с подтверждением больше не используется новым интерфейсом.

«Редактировать» проверяет права повторно при нажатии. Ссылка ведёт в личный
редактор; редактор закрытой тренировки открывается из личного списка тренировок.

История платежей и баланс группы используют границы и чередование строк, как карточка тренировки. Различается только набор и ширина колонок.

## Согласованный финансовый интерфейс

`finance-proposal.html` — одобренный макет, перенесённый в Kotlin.
Правила: [FINANCE_PROPOSAL.md](FINANCE_PROPOSAL.md); состояние установки —
[DEPLOYMENT_STATUS.md](../DEPLOYMENT_STATUS.md). Основной `tennis-flow.html`
содержит прежнее финансовое меню; текущий финансовый сценарий нужно смотреть
в отдельном согласованном макете, а код проверять через `FinanceFlowTest`.
В основном макете обновлена колонка «Играл» в личном списке без времени гостей;
у отменённой тренировки ячейка пустая.

Проверка суммы, отмены и правки без браузера:
`node docs/prototype/check-finance-amounts.cjs`. Она запускает чистые функции
макета, не имитирует браузер и не подтверждает внешний вид в Telegram.
Kotlin-тесты проходят реальные обработчики, базу и имитацию сетевого интерфейса;
измерения исключают задержку настоящей сети. Кнопки сохраняют структуру,
недоступные отключены, новая сумма обновляется в текущей карточке.

Личная сумма в финансовом макете отображается контрастным красным/зелёным
элементом. Нажатие только обновляет экран.

В таблицах баланса и выбора участников два столбца: «Участник / Баланс».
Подсказка: «Нажми на имя для профиля, на баланс — для перевода». Нулевой
чужой баланс тоже кликабелен; свой не предлагает перевод самому себе.

История переводов — только таблица, без дублирующих кнопок записей ниже. Имена
открывают профили, остальные поля — карточку с доступными действиями. Страница
и режим возвращаются после просмотра.

Неуспешная проверка членства не создаёт участника группы. Старые отсутствующие
аккаунты без игр и ненулевого баланса скрыты; история и расчёты сохраняются.

«Баланс группы» показывает только отмечавших участие хотя бы в одной
неотменённой тренировке этой группы. Членство в чате само по себе не добавляет
в список. Выбор участников произвольного перевода использует тот же состав,
порядок и пагинацию по 15 человек. Отправитель остаётся видимым, но выбрать
его получателем нельзя. Имена ведут в профиль, балансы — к оформлению перевода.

«💰 Принять платёж» без счётчика: отключена и нейтральная при отсутствии
ожидающих получения переводов, зелёная (`success`) при их наличии. Состояние
берётся из уже загруженной сводки выбранной группы при отображении экрана;
дополнительных запросов и опроса по таймеру нет. Количество остаётся в тексте
сводки, но не в подписи кнопки.

При успешном ручном вводе сумма меняется в текущей карточке над кнопками;
сообщение пользователя с числом ставится в существующую очередь удаления.
Удаление выполняется фоном после доставки карточки и повторяется при временном
сбое, не задерживая её обновление. Новый перевод вводом не создаётся.
Сумма выделена отдельным заголовком `h1` без блока цитаты и центрирования.
Это самый крупный относительный размер заголовка Telegram; точный шрифт выбирает клиент.
В макете сумма — 32px, жирная, слева; это иллюстрация, а не гарантия размера в Telegram. В колонке «Играл» числа
и заголовок выровнены вправо, у отменённых пусто. Кнопка «Предлагается ботом»
возвращает текущую рекомендуемую сумму и остаётся отключённой при совпадении.

Переход из таблицы балансов выбирает только получателя; сумма нового своего
перевода не заполнена (`— ₽`), запись и округление отключены. Это действует
и при ненулевом балансе получателя. Готовое предложение начинает с рассчитанной
суммы; её можно явно выбрать кнопкой «Предлагается ботом N ₽» и в свободном вводе.

Отправитель может изменить сумму своего перевода до подтверждения получателем,
с отметкой автора правки. Изменение сохраняет ожидание и корректирует резерв;
проводок пока нет. После подтверждения изменение доступно только администратору.
Получатель подтверждает версию, которую видел: после правки старая кнопка
попросит открыть актуальную сумму. Отмена учтённого перевода меняет статус
`transfers` на `CANCELLED`, добавляет действие со снимками до/после и обратные
`balance_entries`; старые проводки сохраняются для истории.

Подтверждение поступления: кнопка «💰 Принять платёж», заголовок «Проверь
поступление», карточка «Деньги пришли?» со ссылкой на отправителя и суммой.
Получатель и балансы не выводятся. Проверка настоящих проводок выполняется
командой приложения `verify`; макет финансовую базу не проверяет.

Кнопка возвращена к подписи «💰 Принять платёж». Тексты после нажатия остаются
«Проверь поступление» / «Деньги пришли?», с отправителем со ссылкой, суммой
и датой без получателя и балансов. Неактивность задаётся `disabled`; степень
визуального приглушения определяет клиент Telegram. Прозрачность в макете
условная и не гарантирует такой же вид в приложении.

## Макет отдельного уведомления

У Алексея показано отдельное уведомление от Бориса на 600 ₽. «📥 Подтвердить получение»
открывает обычную карточку ниже уведомления; сообщение остаётся до подтверждения,
отмены или истечения 12 часов. Изменение суммы не меняет этот срок. Перевод не
подтверждается одним открытием. Отображение — пример, без отправки в Telegram.
Выбор своего получателя и баланс группы имеют одинаковый состав игроков.
