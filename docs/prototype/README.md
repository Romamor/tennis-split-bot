# Интерактивный прототип Telegram-бота

[tennis-flow.html](tennis-flow.html) — автономный фрагмент интерфейса с локальной
моделью тестовых данных. Его можно открыть как HTML в браузере или встроить в
оболочку просмотра. В разговоре показывается тот же фрагмент; копия в Git нужна
для совместного обновления с кодом и документацией.

Обновлено для выпуска с календарём, настройками начала и снятием закрепов. Фактическая установка бота
описывается в [DEPLOYMENT_STATUS.md](../DEPLOYMENT_STATUS.md).
Прототип не подключён к Telegram, базе или серверу. Выбор роли, ввод, переводы,
закрепление и системный выбор аккаунта работают только с демонстрационными данными.
Перезагрузка страницы начинает сценарий заново.

## Что можно пройти

- Три роли, две изолированные группы, личный и общий чат.
- Создание тренировки любым участником, последовательные название / дата / время,
  проверка перед публикацией и предупреждение о несохранённом вводе.
- Присоединение с 0 ч, полная таблица, несколько гостей, время ±0,5/±1 ч,
  оплата ±5/±50/±100 ₽ и сохранение оплаты после выхода.
- Учёт создателем или администратором; учтённая тренировка не появляется у автора
  только из-за авторства. Участие и оплата остаются самостоятельными основаниями.
- Массовый выбор игроков, административная форма с «Всё правильно», изменение
  деталей, отмена, восстановление и применение нового расчёта.
- Расчёты, запись произвольного перевода, проверка дубля за сутки, правка суммы,
  уточнение и отмена записи, история изменений, нулевые балансы.
- Список ролей, назначение и снятие администраторов только суперадминистратором.

Модель повторяет основные правила распределения по игровому времени и отдельным
гостевым местам. Это не замена тестам расчётного ядра: ошибки сети, параллельная
правка с другого устройства и реальные разрешения Telegram здесь не воспроизводятся.
Административный ввод показывает 0 ч при массовом добавлении, как выполняет
SettlementService; старая текстовая подсказка в Screens ещё упоминает 1 ч.

## Проверка и обновление

Проверено нажатием кнопок в браузере: создание без участия, учёт и фильтр автора,
новые шаги оплаты, гости и выход, правка состава, переводы, назначения, возвраты
и несохранённый ввод. Также пройдены дубль перевода, отмена и восстановление,
27 строк без страниц, тёмная тема и изоляция второй группы; ошибок JavaScript нет.
Дополнительные сценарии описаны в
[UI_REGRESSION_SCENARIOS.md](../UI_REGRESSION_SCENARIOS.md).

При изменении бота прототип **не обновляется автоматически**. В том же наборе
правок нужно сверить подписи и переходы в Screens, права и команды в
SettlementService / SelfServiceBot, обновить прототип и
[схемы по ролям](../diagrams/README.md). Не считать успешные проверки Kotlin
проверкой этого отдельного JavaScript-прототипа.

Для повторной браузерной проверки подготовить оболочку и запустить сценарии
в окружении с установленным Playwright и его Chromium:

```sh
python3 docs/prototype/render-preview.py /tmp/tennis-prototype.html
node docs/prototype/check.cjs /tmp/tennis-prototype.html
node docs/prototype/check-extra.cjs /tmp/tennis-prototype.html
node docs/prototype/check-calendar.cjs /tmp/tennis-prototype.html
```

Вместо Chromium Playwright можно задать путь к локальному Chrome через `CHROME_BIN`.
Тесты используют отдельный временный профиль, не входя в настоящие аккаунты.

В форме создания добавлены стрелки даты и две колонки начала — часы / минуты.
Стрелки над и под значениями меняют часы на 1, минуты на 30; числа не меняют ввод.
В настройках администратора — время начала новых тренировок для выбранной группы,
по умолчанию18:30. Учёт и отмена меняют состояние закрепа; восстановление не закрепляет
автоматически. Одна текущая панель макета соответствует новому правилу личного меню.
