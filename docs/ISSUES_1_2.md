# Карточка тренировки и пользовательская панель

Реализация требований и сверка приложенных макетов задач [#1](https://github.com/Romamor/tennis-split-bot/issues/1)
и [#2](https://github.com/Romamor/tennis-split-bot/issues/2).
Состояние установки — в [DEPLOYMENT_STATUS.md](DEPLOYMENT_STATUS.md).

| Требование | Реализация |
| --- | --- |
| Убрать блок группы, показать название и дату | Общая и персональная карточки используют один генератор содержания |
| Участники таблицей | Нативная таблица rich message: имя со ссылкой, время, оплата, баланс тренировки |
| Пустой состав | «Пока никто не зарегался» |
| Вход через Open | «Открыть» показывает личную панель; «Присоединиться» записывает 0 ч и 0 ₽ |
| Гости отдельными строками | «Имя гость N», без создания Telegram-аккаунтов; до 99 гостей |
| Гости играют столько же | Новый ввод синхронизирует время всех гостей с пригласившим |
| Интерактивная оплата | Подменю с ±1, ±10, ±100, ±1000 ₽; запись каждого изменения сразу |
| Интерактивное время | Подменю с ±0,5 ч и ±1 ч; время не становится отрицательным |
| Не играл, но заплатил | «Не участвую» сохраняет оплату, строка плательщика остаётся |
| Панели с одинаковыми данными | Обновляются общая и уже открытые персональные таблицы |
| Edit для администратора | «Редактировать» ведёт на эту тренировку в личный чат |
| Закрепление с уведомлением | Запрос pinChatMessage с уведомлением; отказ права виден администратору |
| После учёта нет пользовательского редактирования | Панели участников закрываются; старые кнопки и повторный вход отклоняются |

Вложенные изображения просмотрены: первое задаёт структуру карточки, второе
показывает прежнюю персональную панель, третье — целевую схему переходов.
Гости добавляются и удаляются прямо с основной панели, без промежуточного меню.
Оплата и время расположены отдельными строками; в подменю положительные поправки
стоят над отрицательными, «Назад» и «Закрыть» — рядом. Английские подписи макета
переведены на русский, финансовое состояние «Учтена» сохранено. Числа в схематической
таблице не меняют правило пропорционального расчёта по игровому времени.

На общей карточке одна основная кнопка «Открыть». По уточнению владельца состав
одной тренировки показывается целиком, включая гостей: в группе, личном чате
и персональных панелях, во всех состояниях. Пагинация остаётся в списках и истории.
Закрепление не повторяется при редактировании и перезапуске.
При неизвестном результате закрепления нужен осознанный повтор администратора.

В пользовательской панели больше нет подтверждения «Всё правильно»: запись и
история меняются при каждом успешном нажатии. Дубликат события и действие без
изменения значения не добавляют правку. В форме администратора и массовом выборе
сохраняется подтверждение всего ввода с защитой от параллельного изменения.
Администратор видит неиграющих плательщиков и может исправить их оплату без
повторной записи в участники.

Колонка «Баланс» показывает оплату минус долю расходов по конкретной строке.
Гостевые доли отдельно видны в таблице и суммируются на аккаунте пригласившего
при учёте. Это предварительные значения: общий баланс группы меняется только
после «Учесть тренировку» / «Применить правки». Оплата при отсутствии указанного
времени пока не распределяется; таблица показывает «—» и подсказку.

Схема 3 сохраняет прежнюю финансовую историю и старое время единственного гостя.
Неизменённое подтверждение старой строки ничего не переписывает; следующий реальный
ввод времени/участия применяет новое правило. [Таблицы базы](DATABASE_V2_TABLES.md).
Годовая модель нового ввода занимает 14,59 МиБ; ориентир с запасом — 20–25 МиБ.
[Допущения и результаты](STORAGE_REVIEW.md).

Прошли 93 автоматических теста, сборка, демонстрационный расчёт и годовая
симуляция. Проверены формат запросов, роли, повторы, переполнение сумм и миграция. Поддержка таблиц и персональных сообщений зависит от клиента Telegram;
автоматические тесты не подтверждают внешний вид на конкретном устройстве.
