# Диагностика памяти сервера

Замеры конкретных машин и состав сторонних служб не входят в публичную документацию.
Здесь приведён общий порядок диагностики, применимый к установке бота.

1. Проверить `free -m`: ориентироваться на MemAvailable, отдельно учитывать подкачку.
2. Посмотреть `vmstat 1 5`: обмен с подкачкой, загрузку процессора и ожидание диска.
   Первая строка — среднее с загрузки системы; следующие строки — текущие интервалы.
3. Сопоставить `docker stats` с memory.current и memory.swap.current в cgroup v2.
   Низкое потребление RAM может означать выгрузку памяти процесса в подкачку.
4. Проверить события OOM, перезапуски контейнера, ограничения памяти и нагрузку диска.
5. На VMware при доступности прочитать /sys/kernel/debug/vmmemctl: ballooning
   означает, что гипервизор забирает часть памяти гостевой системы. Количество
   страниц нужно умножить на размер страницы, а причину политики уточнять у провайдера.

Не складывать пересекающиеся показатели RAM, кэша и RSS. Не отключать подкачку,
драйверы и другие службы без выяснения причины. После перезагрузки дать закончиться
старту служб; временное улучшение не доказывает устранение причины.

[VMware: влияние лимитов памяти](https://knowledge.broadcom.com/external/article/326270/impact-of-virtual-machine-memory-and-cpu.html).
