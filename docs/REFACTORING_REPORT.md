# Общий рефакторинг — 23 октября 2026

Структура меняется без изменения пользовательских действий, схемы 9, форматов
событий, команд и денежного журнала. Состояние установки указано в
[DEPLOYMENT_STATUS.md](DEPLOYMENT_STATUS.md). До правок сделана согласованная
копия рабочей SQLite, скачана с сервера и проверена локально: контрольная сумма,
целостность, внешние ключи и финансовая сверка. Сама копия находится вне Git.

## Найденные повторы и решения

| Область | Было | Стало |
| --- | --- | --- |
| Создание перевода | Четыре варианта INSERT и повторное чтение новой строки в двух ветках | Одна `insertTransfer` в `storage/TransferRepository.kt`; запись один раз читается для истории и проводок |
| Участие | Одинаковое удаление / INSERT ON CONFLICT для мгновенной правки и подтверждённого черновика | Одна `saveAttendance` в `storage/TrainingRepository.kt` |
| Страницы | Формулы ограничения номера страницы и drop/take повторялись в службе и экранах | `application/Pagination.kt`: общие границы; копируется только видимый диапазон |
| Старые сообщения | Повторялись удаление и очистка кнопок при отказе Telegram удалить старое сообщение | Общий путь в `MessageDelivery`; отдельные правила повторных попыток меню и уведомлений сохранены |
| Ввод тренировки | Создание, редактирование и личные параметры находились в большом диспетчере | `TrainingInput` владеет шагами этих форм; общая защита выхода остаётся перед диспетчеризацией |
| Проверки команды | После полного выбора типа команды стояла недостижимая дополнительная ветка проверки администратора | Удалена; действующие проверки каждой команды сохранены |

Проверки доступа не объединены с записью в базу: обычный перевод ожидает получателя,
административная запись применяется сразу, исторические команды сохраняют свои
проверки. Эти различия нужны для правил и воспроизведения старой истории.
Не вводились универсальный каркас обработчиков, новые библиотеки, таблицы,
фоновые процессы или дополнительные запросы Telegram.

[Результаты измерений](measurements/refactoring-20261023.json) содержат счётчики
и результат сравнения каждого шага; все исходные данные искусственные.

  размеры страниц 3/5/8/10/15, пустые списки, устаревший номер после удаления,
  отрицательные номера и независимость видимого результата от изменения списка.
- 324 сохранённых описания экранов старой и новой сборки совпали: текст, HTML,
  порядок и цвета кнопок, действия и переходы. Случайные токены сравнивались
  через соответствующие им действия. Внешний вид настоящих клиентов не проверялся.
- `scripts/CheckRefactoring.java` воспроизводит 27 действий на искусственной базе.
  После **каждого** шага у старого и нового JAR совпали результат или отказ,
  записи тренировок, участников, переводов, назначения, история и проводки.
  Включены закрытие, повторное открытие, ввод черновиком и напрямую, подтверждение,
  исправление, отмена, старые команды и запрет доступа из другой группы.
- Число прикладных SQL-запросов на этих шагах не выросло. Административная запись
  перевода: 16 → 15; историческая запись: 14 → 13. Остальные шаги без изменения.
- Список из 100 открытых опросов: прежние 21 SQL-запрос, 2 транзакции чтения и
  1 записи. Ускорение сети и снижение памяти сервера этим измерением не заявляются.

Дифференциальная проверка означает запуск одинаковых действий в двух версиях и
сравнение результата. Для повторения после `installDist` запусти скрипт с прежним
и новым набором JAR, каждый раз с новым путём искусственной базы:

```sh
java -cp 'path/to/distribution/lib/*' scripts/CheckRefactoring.java temporary-fixture.sqlite
```

В строках JSON должны совпасть `step`, `outcome` и `snapshot`; `sql` сравнивается
отдельно. Скрипт отказывается открывать существующую базу и не использует Telegram.

## Что изменено

| Область | Результат |

| Отображение | NavigationScreens отвечает за навигацию и настройки; PollScreens — за опросы; HistoryDescriptions — за текст истории. Screens сохраняет общий контроль длины, уведомления и токены кнопок. |
| Обработка событий | PollWorkflow выполняет публикацию, остановку, повтор и отмену опроса. SelfServiceBot передаёт ему проверенный контекст и функцию проверки права публикации. |
| Настройки группы | GroupSettings сохраняет атомарное изменение настройки и правил открытых тренировок; SettlementService оставляет прежний интерфейс вызовов. |
| Доступ к базе | PollRepository фильтрует и выбирает страницу до создания объектов Kotlin. GroupAccessRepository объединяет запросы проверки роли и членства. |
| Создание тренировки | Обычное создание и завершение опроса используют одну insertTraining, которая записывает актуальные правила сразу в INSERT. Отдельный UPDATE после создания больше не нужен. |

## Измерения

Сценарий: первая отрисовка списка из **100 незавершённых опросов**, группа с
40 искусственными аккаунтами, просматривает назначенный администратор бота.
На странице пять опросов; их создатель — другой аккаунт.

| Показатель | До | После |
| --- | ---: | ---: |
| Прикладные SQL-запросы на открытие списка | 119 | 21 |
| Транзакции чтения | 102 | 2 |
| Транзакции записи кнопок | 1 | 1 |
| Полных объектов опроса, загруженных для страницы | 100 | 5 |
| Screens.kt, строк | 546 | 407 |
| SelfServiceBot.kt, строк | 907 | 875 |
| SettlementService.kt, строк | 556 | 534 |
| Исходных файлов Kotlin | 28 | 34 |
| Строк Kotlin всего | 3 829 | 3 940 |
| JAR приложения, байт | 710 619 | 737 089 |

Число SQL-запросов этого сценария уменьшилось примерно на 82%, транзакций чтения —
на 98%. Это измерение на искусственных данных, не обещание такого же сокращения
задержки Telegram. sqlTrace считает прикладные запросы, без BEGIN / COMMIT.
SQLite всё ещё должна посчитать подходящие строки и отсортировать страницу;
не утверждается, что движок физически читает только пять строк.

Сборка выросла на 26 470 байт, около 3,7%: разделение кода добавило классы.
Экономии места в JAR нет. Суммарный исходник тоже вырос за счёт явных границ модулей.
Новые библиотеки, таблицы, индексы, журналы и дополнительные фоновые процессы
не добавлены. Скорость роста базы от рефакторинга не меняется. Постоянное снижение
RAM на рабочем сервере не измерялось; подтверждённый эффект — ограниченная загрузка
объектов страницы и уменьшение числа обращений к SQLite.
