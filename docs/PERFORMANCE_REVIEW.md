и отдельный измерительный сценарий. Статус установки указан

## Измерения

Стенд `PerformanceAuditTest` использует настоящий обработчик, SQLite, службы и
рендеринг. Telegram заменён имитацией без сети. Данные искусственные: 40 известных
аккаунтов, 20 игроков в тренировке, 1/10/20 персональных панелей. Для меню бот знает
1/5/20 групп, пользователь состоит в одной из них, там включены опросы.

Измерения проведены локально, после предварительного прохода, по пять повторов
основных сценариев. Время на VDS, сеть, ожидание между порциями и расход RAM
этот стенд не измеряет. SQL-счётчик не включает PRAGMA, BEGIN/COMMIT и внутреннюю
работу SQLite. Число открытых соединений после оптимизации измеряется отдельно
от числа транзакций. Результаты: [до](measurements/performance-audit-20261002.json),

Число транзакций выросло из-за проверок очереди между порциями, но они больше не

уменьшилось умеренно: остальные пользователи всё ещё должны получить свежие данные.
Главное изменение — возможность принимать новые события между небольшими порциями.
Остальные экраны обновляются постепенно; полная сходимость может занять дольше,
чем один непрерывный проход без приёма новых событий.

Изолированный контроль на новом коде: обработчик с прежним открытием соединений —
12,82 мс; с дополнительным бездействующим соединением — 5,40 мс; с реализованным
повторным использованием соединений — 1,27 мс. Это медианы 12 повторов. Нельзя
переносить это отношение на время сетевого ответа или обещать такое же снижение RAM.

## Персональные панели и очередь

Общий отказ 400/403 или временный сбой фонового редактирования больше не удаляет
ID ещё видимого окна. Бот сохраняет ID и старые кнопки при определённом отказе,
а при неопределённом результате сохраняет и потенциально доставленные кнопки.
ID забывается только при явном отсутствии сообщения или принятом удалении.

`bot_sessions.panel_json` содержит экран и служебные поля `rendered_version`,
`refreshed_at`, `retry_after`. Схема остаётся 9, новых таблиц нет. Внутренние поля
не входят в команды кнопок. Старые записи без версии считаются требующими обновления.

После успешного показа сохраняется версия увиденной тренировки. Уже актуальная
панель автора не обновляется второй раз. За порцию обрабатываются до двух общих
карточек и четырёх персональных панелей; очередность учитывает давность обновления.
Повтор читает последнюю версию, промежуточные состояния не рассылаются заново.
Незавершённая очередь персональных панелей сохраняется при перезапуске.

Для сетевых запросов одной порции обслуживания задан общий бюджет 5 секунд;
тайм-аут очередного запроса не больше оставшегося бюджета. После исчерпания новые
запросы откладываются, и цикл возвращается к получению событий. Это не жёсткая
гарантия времени на перегруженной ОС. Ограничение частоты Telegram сохраняется.
У неудачной доставки есть задержка повтора; одна ошибочная панель не удаляется
и не препятствует обработке других получателей. При наличии очереди ожидание
в `getUpdates` сокращается с учётом ближайшей попытки.

Старые окна, от которых Telegram уже не присылает события, этим не удаляются
задним числом. Принятая команда удаления также не гарантирует исчезновения окна
в каждом клиенте Telegram — это по-прежнему отдельная проверка.

## Навигация и права

Главное меню и настройки используют известные группы пользователя. Полный поиск
выполняется при явном выборе группы и для пользователя без известных групп.
Результаты проверок для навигации кэшируются на 30 секунд, максимум 256 записей;
события изменения состава или прав сбрасывают кэш соответствующей группы.

Перед защищённым действием членство и роль проверяются заново через Telegram.
Навигационный кэш не используется для разрешения финансовой операции, изменения
настроек, управления администраторами или публикации. В частности, тёплый кэш
не позволяет ушедшему участнику открыть управление тренировкой или бывшему
администратору изменить правила группы. Первичный поиск групп всё ещё требует
сетевых запросов; результат 23 → 2 относится к повторному показу меню.

## SQLite и записи

В рабочем процессе удерживаются до двух свободных соединений. Это позволяет
читать во время пакетной записи кнопок, сохраняя прежнюю изоляцию транзакций.
Соединения закрываются при выходе из рабочего блока, в том числе при исключении.
Одно изменение по-прежнему записывается атомарно, режим `synchronous=FULL` сохранён.
Команды backup/verify продолжают использовать источник только для чтения.

Раньше закрытие последнего соединения обычно переносило WAL в основной файл
и удаляло WAL/SHM после каждой короткой операции. Теперь журнал живёт во время
работы бота. Подробности — [SQLite WAL](https://www.sqlite.org/wal.html#the_wal_file)
и [правила резервного копирования](BACKUPS.md).

Кнопки обновляются по разнице наборов; актуальные записи не выключаются и не
включаются заново. Прежние кнопки сохраняют двухминутный срок. Аккаунты, названия
групп и членство не переписываются при неизменившихся значениях. Отметка доставки
обновляет только ещё не отмеченные действия. Посещаемость пересчитывается при
изменении участия или состояния учёта, а не при каждом изменении оплаты/времени.
История проводок проверяется при их изменении; полная проверка остаётся в verify.
История действий и финансовые записи не удаляются.

## Проверки и повтор запуска

Проверены: отказ обновления с сохранением одного окна; продолжение очереди после
перезапуска; сходимость к последней версии после нового нажатия; изоляция отказа
одного получателя; отзыв членства/прав при тёплом кэше; срок/ограничение кэша;
откат транзакции, вложенное чтение, закрытие соединений и копирование данных из WAL;
отсутствие перезаписи неизменных кнопок и старых отметок доставки; ограничение
фонового бюджета без влияния на последующий пользовательский запрос.

```sh
sh scripts/gradle.sh test --no-daemon
sh scripts/gradle.sh performanceAudit -PauditDir=build/performance-audit-new --no-daemon
```

Каталог измерений должен быть новым или пустым. Измерительный стенд не входит
в обычную задачу test и не подключается к Telegram. На сервере отдельно проверяются
свежий запуск, версия пакета, целостность базы и новые действия пользователя.
