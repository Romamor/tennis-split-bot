## Измерение

Одна новая карточка в сценарии сравнения: отдельная подготовка 8 кнопок требует
8 транзакций записи, подготовка всего экрана — 1. Чтение списка трижды не содержит
запросов к training_players для пересчёта посещаемости. Эти числа не являются
замером задержки Telegram или общим количеством запросов за пользовательский ход.

## Границы

Подставной Telegram и локальный HTTP-сервер не доказывают, что конкретный клиент
Mac показывает персональную панель или открывает профиль при его настройках приватности.
Это остаётся отдельной живой проверкой после разрешённой установки.

## Добавлено при ревью хранения

- `completed event plans are released while incomplete recovery and financial history survive`:
  очищаются только планы завершённых событий, сохраняются номера, незавершённые планы и история.
- Проверки повтора ответа теперь имитируют сбой триггером SQLite **до** отметки завершения,
  а не превращают уже завершённое событие в незавершённое задним числом.
- `balance filter toggles do not accumulate an unbounded return chain`: 25 переключений
  не увеличивают размер команды.
- `DatabaseMaintenanceTest`: исходная версия 1 и байты источника не меняются при
  копировании и проверке; копируются данные из активного WAL, восстановление сохраняет
  историю и балансы, права копии — 0600, перезапись существующего файла запрещена.

Отдельная задача `storageSimulation` не входит в обычный прогон тестов. Модельный год
40/10/156 выполнен до и после очистки планов; финансовая история совпадает по SHA-256.

## Создание участником и право учёта

- Обычный участник создаёт тренировку, находит её в «Моих тренировках» без участия,
  переходит к проверке расчёта и подтверждает учёт. После учёта запись исчезает
  у создателя, который не играл и не платил, но остаётся у участвовавшего человека.
- Другой участник не видит кнопку учёта; поддельная команда и экран проверки
  отклоняются. Назначение администратора в соседней группе не даёт права учёта.
- Создатель после выхода из группы не может создать или учесть тренировку;
  в том числе через уже открытую форму подтверждения. Администратор группы может
  учесть тренировку ушедшего создателя.
- Создатель правит игроков и детали только своей тренировки; не получает прав
  отмены, восстановления и управления группой.
- Шесть кнопок оплаты: +5/+50/+100 и −5/−50/−100 ₽; проверены суммы, состав рядов
  и обработка переполнения без изменения данных.

## Календарь, закрепы и уборка меню

- Учёт и отмена снимают только конкретную карточку в её группе, не удаляют сообщение
  и не затрагивают другие закрепы; успех не повторяется после перезапуска.
- Старые закрытые записи с NONE и прерванное снятие обрабатываются после запуска.
  Временный сбой повторяется; отказ прав доступен для ручного повтора администратором.
  Закрытую карточку с отложенным закреплением нельзя закрепить снова.
- Восстановление отменяет ожидающее снятие; отсутствующее сообщение завершает уборку.
- Личная панель переносится вниз после текста, старое меню удаляется после доставки;
  отказ удаления по возрасту заменяет его пометкой без кнопок. Очередь переживает
  перезапуск; старый callback убирает старое, а не текущее меню.
- Стрелки даты: январь31 → февраль29 → следующий год февраль28; переход суток.
  Стрелки начала: два столбца часов / минут, текущие значения между стрелками,
  шаги ±1 час / ±30 минут. Нажатие на число сохраняет форму без изменений;
  18:30 → 19:00 при увеличении минут; переход через полночь не меняет дату.
- Настройка начала доступна администраторам своей группы, не меняет прежние тренировки
  и не перезаписывается обновлением чата. Одновременное изменение отклоняется.
- PinMigrationTest проверяет настоящий DDL схемы3, сохранение данных доставки,
  добавление времени18:30 и доступность новых состояний снятия закрепа.

- Пункт «Администраторы группы» находится только в настройках суперадминистратора;
  возврат из списка ведёт в настройки. Назначенный администратор этого пункта не видит.
  Назначение и снятие роли по-прежнему изолированы по группе.

## Карточка и три статуса тренировки

- Общая карточка во всех статусах: ровно одна строка с одной кнопкой «Открыть».
- Основная персональная панель: «Редактировать» только создателю, администратору
  Telegram и назначенному администратору данной группы, до и после участия.
- Подменю времени / оплаты и управление игроком не содержат «Редактировать».
- Чужая персональная кнопка не открывает редактор; закрытые состояния сохраняют
  маршрут редактирования из личного списка. Полоса закрепа проверяется в Telegram отдельно.
- Создатель и администратор входят в редактор; посторонний участник и ушедший создатель — нет.
- Для CLOSED и CANCELLED участник, создатель и администратор получают alert с «ОК»
  при открытии и каждом старом переходе / изменении времени, оплаты и гостей.
  Запись тренировки и число финансовых действий не меняются.
- CLOSED → OPEN немедленно отменяет прежний расчёт, сохраняет ввод и переводы.
  Повторный учёт не удваивает баланс. Отмена открытой тренировки не отменяет его повторно.
- Миграция схемы4: REVIEW → OPEN с компенсирующей операцией; другие группы,
  реальные переводы и прежние записи истории неизменны; повторный запуск ничего не повторяет.
- История со старыми JSON-снимками REVIEW читается; новые тренировки этот статус не принимают.
- В карточке нет фразы «Баланс указан по этой тренировке».

- Обновление старых карточек не публикует удалённые учтённые / отменённые сообщения заново.

## Личные настройки и создание без предварительной группы

- Главное меню и настройки работают без единой группы; глобальные кнопки имеют NULL group_id.
- «Настройки» → «Тренировка»: точный текст и кнопки Название / Время / (Назад, Меню).
  Настройки одного пользователя не меняют настройки другого и сохраняются при обновлении аккаунта.
- Название → дата → время → группа → проверка; ввод сохраняется при каждом возврате.
  На проверке только Опубликовать / (Назад, Отмена); отмена любого шага сразу открывает главное меню.
- В выборе группы исключены вышедший пользователь, вышедший бот и бот без администраторских прав.
  Потеря прав после показа списка или перед публикацией не создаёт тренировку.
- Группы по 8 на странице; возврат с проверки восстанавливает страницу выбора группы.
- «Мои тренировки»: статистика всех групп, 8 записей на страницу, сортировка по created_at,
  а не played_on. Отменённые и открытые записи остаются в списке, но не входят в количество,
  время и стоимость участия в статистике.
- Карточки OPEN / CLOSED / CANCELLED показывают только разрешённые Открыть / Редактировать / Назад;
  возврат сохраняет страницу общего списка. Пояснения об отмене нет.
- Миграция5 → 6 сохраняет финансовые записи и старые кнопки; добавляет личные значения,
  убирает групповое время, переносит незаконченные формы и сохранённые события к новому порядку.

## Редактор с немедленным управлением игроками

Текущий редактор заменяет описанный выше массовый выбор с подтверждением и форму
«Всё правильно». Проверки старых сохранённых форм остаются для восстановления
прерванных событий; новые меню их не создают.

- `EditorFlowTest`: точные ряды кнопок и возврат по источнику входа, запрет чужому участнику, доступ создателю и администратору.
- Добавление сразу убирает имя из списка; ушедшие участники не предлагаются. Исключение с оплатой отклоняется без записи истории и без удаления данных.
- Время, оплата и гости изменяются у выбранного игрока; в истории автором остаётся редактор. Вложенные меню без «Закрыть» возвращают к тому же игроку.
- Четыре перехода статуса, откат только расчёта тренировки, сохранность реальных переводов, повтор события без повторного финансового эффекта.
- Старые кнопки времени / оплаты / гостей после отмены показывают окно ошибки. Снятие роли блокирует сохранённые административные кнопки.

## Проверка редактирования до перехода в личный чат

- Кнопка «Редактировать» в персональной панели содержит callback, а не URL.
  Старые общие кнопки тоже продолжают проверять права. Обычный участник,
  включая администратора другой группы, получает ошибку с «ОК» в текущем чате.
- Отказ не отправляет сообщений, не меняет открытые личные панели и финансовые записи.
- Создатель, администратор Telegram и назначенный администратор бота получают
  переход из персональной панели открытой тренировки. Для всех трёх статусов
  редактор доступен из личной карточки. При входе по ссылке права проверяются повторно.
- Снятые права блокируют в том числе повтор сохранённого события. Подмена группы
  и недоступная проверка членства не приводят к переходу.
- HTTP-проверка: `answerCallbackQuery` с URL только для разрешённого перехода,
  `cache_time=0`; отказ — `show_alert=true` без URL.

## Закрытие персональных панелей

`BotStartupTest`: временные ошибки и ограничение частоты повторяются в той же
сессии запуска, отказ авторизации не повторяется, остановка прерывает ожидание.
`BotRuntimeCycleTest`: ошибка фонового обслуживания не мешает обработать уже
полученные события; пустая очередь завершает ранее остановленные опросы до
новой остановки в обслуживании, сохраняя порядок учёта последних голосов.

Закрытие персональной панели (`SelfServiceBotTest`): недоступная проверка
членства не мешает скрыть собственную панель; временный сбой удаления оставляет
событие незавершённым и повтор закрывает ту же панель. Повторное открытие при
сбое обновления не создаёт второго сообщения; панели других пользователей
сохраняются. Постоянный отказ виден в окне ошибки, кнопка доступна для повтора.
Устаревшая кнопка без необязательного поля получателя удаляет только панель
нажавшего пользователя. Финансовые операции при закрытии не создаются.
Сбой после доставки, но до завершения события: Telegram повторно использовал
ID старой панели; повтор обработки не удаляет новую и не отправляет ещё одну.

## Мои финансы: отправка и принятие

- В «Балансе группы» на каждой странице имя связано с профилем именно этой
  строки. Имена с символами `<`, `>` и `&` безопасно отображаются в ссылке;
  текстовое представление таблицы содержит имена без разметки ссылок.
- При наличии @username баланс группы и карточка тренировки используют
  публичную ссылку `https://t.me/username`; без него сохраняется ссылка по ID.
  Это проверяется в таблице с несколькими страницами и в карточке с гостями.
  Реальная доступность ссылок по ID ограничивается приватностью Telegram;
  автоматические тесты проверяют содержимое сообщения, а не эти настройки.

- Старые финансовые кнопки, сохранённые планы команд и незавершённые формы
  открывают нынешнее меню и не проводят перевод.
- Ранее отменённый перевод виден сторонам в «Истории платежей» и деталях со
  статусом «Отменён», не попадает в принятие и не меняет баланс.

- Сразу после выбора группы текст показывает личный текущий баланс: плюс — получить,
  минус — внести, ноль — `0 ₽`. При отсутствии ожидающих нет строк с нулями.
- Отправитель видит число и суммарную сумму отмеченных отправленных платежей;
  получатель — число и сумму входящих к подтверждению. Кнопка принятия показывает
  тот же счётчик. Обе суммы вычисляются только внутри выбранной группы.
- До подтверждения получателем показанный баланс не меняется; после него сумма
  исчезает из ожидания обеих сторон и баланс обновляется. Администраторский платёж,
  учтённый сразу, не считается ожидающим.

- При нескольких доступных группах выбор обязателен; при одной он пропускается. В другой группе нет платежей и предложений первой.
- Отправитель видит три предложения на странице. Назад из инструкции сохраняет страницу.
- Отметка отправки создаёт «В процессе», не меняет баланс и убирает сумму из предложений.
- Устаревшая сумма, другой получатель и параллельные разные запросы не обходят резерв.
- Подтверждает только текущий получатель. Отправитель, другой администратор и бывший
  участник не могут принять платёж. Принятие добавляет проводки один раз.
- Повтор Telegram-события и новое нажатие уже принятого платежа не повторяют проводок.
- Принятие: три записи на страницу, нажатая строка исчезает; история: пять строк,
  две стороны, сумма, дата и два статуса. Баланс группы: десять строк на страницу.
- Пустые списки отправки и принятия содержат точный текст «Нет доступных платежей».
- Старые кнопки, формы и сохранённые команды не записывают перевод по прежним правилам.
- Открытие учтённой тренировки и перезапуск бота сохраняют ожидающий перевод;
  принятие затем учитывает именно реальный перевод независимо от тренировки.

Проверки: `FinanceServiceTest`, `FinanceFlowTest`, обновлённые сценарии
`SelfServiceBotTest` и браузерный `docs/prototype/check-finance.cjs`.

### Ожидание и следующая тренировка

- Отправить 150 ₽ без подтверждения: доступных отправок нет.
- Учесть следующую тренировку с новым остатком 250 ₽ тому же человеку:
  в отправке только 250 ₽; прежняя запись 150 ₽ неизменна.
- Отправить 250 ₽: получатель видит обе суммы. Принять сначала 250 ₽,

- Устаревшая отправка 150 ₽ после появления предложения 250 ₽ отклоняется.
- История и должники содержат `bordered striped compact`, как карточка тренировки.

Проверки: новые сценарии в FinanceServiceTest и FinanceFlowTest;
общая настройка таблицы закреплена проверками HTML в обоих финансовых разделах.

## Закреп стартового меню

- `/start` в группе публикует одно меню и закрепляет его с `disable_notification=true`.
- `/menu` и повторный `/start` используют тот же message_id; повтор доставки
  одного события не создаёт ни меню, ни дополнительной попытки закрепления.
- Явная команда восстанавливает вручную снятый закреп; удалённое меню заменяется.
- Учёт и отмена тренировок снимают только их закрепы, не затрагивая меню своей
  или другой группы.
- Ранее опубликованное меню с pin_status=NONE закрепляется после обновления
  без новой публикации; очередной перезапуск не повторяет завершённую попытку.
- Неопределённая попытка тихого закрепления и прерванная SENDING продолжаются
  после перезапуска. Отказ в правах ждёт явной команды после исправления прав.
- Неопределённая отправка меню без message_id не дублируется и не закрепляется.
- Карточки тренировок по-прежнему запрашивают закрепление с уведомлением.

Проверки: GroupMenuPinTest и проверка HTTP-параметра в HttpTelegramApiTest.

## Полный выход из тренировки

«Не участвую» удаляет строку участника, оплату, время и гостей в собственной
панели (в группе и личке), а также при управлении игроком администратором.
Общая карточка и открытые панели других участников больше не показывают строку;
кнопки оплаты ушедшего исчезают. Повторный выход не создаёт лишнюю историю,
повторный вход начинается с нулей. Отдельные переводы, история, другие тренировки
и группы сохраняются. CLOSED / CANCELLED по-прежнему отклоняют старые кнопки.

## Опросы перед тренировкой

1. По умолчанию кнопки создания опроса нет; обычная тренировка доступна.
2. Админ включает опросы в одной группе; соседняя группа не появляется в выборе.
   Неадмин может создать опрос, но не менять разрешение. Потеря членства / прав бота
   или отключение настройки после заполнения формы блокирует публикацию.
3. Четыре ответа: −30 мин, начало, +30 мин, свой текст отказа. У полуночи указать
   соседнюю дату. Назад сохраняет форму, отмена возвращает меню, публикация повторно не отправляет опрос.
   Без фото экран публикации сразу предлагает «Опубликовать».
   Необязательная кнопка «Добавить фото» просит прислать фото; текст вместо фото
   оставляет подсказку. После фото появляется прежний экран публикации, можно
   заменить и убрать изображение. После перезапуска черновик сохраняет выбранное
   фото; опубликованный опрос содержит его внутри, повтор отправки использует тот
   же файл. Обычная тренировка и опрос без фото работают как прежде.
4. Повтор / смена времени сохраняет одну строку списка. Отказ / отзыв удаляет её;
   отказавшийся новым аккаунтом не записывается в users. Голос не создаёт сообщение,
   действие в истории или тренировку; bot_events не содержит ответа / автора голосования.
5. Кнопка под опросом у постороннего выдаёт попап. Создатель и админ именно этой группы
   получают подтверждение; права другой группы не подходят. Личная панель принадлежит нажавшему.
6. После подтверждения закрыть голосование, включить ответы из очереди, затем создать
   одну тренировку с исходным автором. Только записавшиеся, **0 ч, 0 ₽, без гостей**.
   Один actions, ноль проводок; poll_signups очищена. Закреп переносится на карточку.
   Фото из опроса входит в эту же закреплённую карточку над таблицей и остаётся
   после правки состава; второго сообщения и закрепа нет. Без фото карточка прежняя.
7. Перезапуск на закрытии и повторное завершение не дублируют тренировку.
   Ответы неизвестному или завершённому опросу игнорируются.
8. Выключение настройки не мешает завершить старый опрос. Список «Мои опросы» разбит по пять.
9. Неопределённая отправка не повторяется автоматически и не превращается в тренировку
   с неполным составом. Отмена неудавшейся публикации не создаёт тренировку.
10. Миграция 6 → 7 сохраняет проводки, историю, личные настройки и выключает новую
    возможность по умолчанию. Повторное открытие базы ничего не мигрирует заново.

Автоматизация: PollFlowTest, PollMigrationTest и HttpTelegramApiTest.

## Правила гостей и времени

1. Новая группа: гости разрешены, время включено. Настройки меняет только админ
   этой группы; другая группа не меняется.
2. Время выключено: присоединение / повторное присоединение после выхода,
   массовое добавление админом / Telegram-выбор и перенос из опроса дают 60 минут и 0 ₽.
   В карточках public / my_training / training / participation нет колонки времени;
   в обычной и административной панели нет кнопки длительности.
3. Гости запрещены: нет добавления гостей и пустых рядов клавиатуры. Старые GUEST,
   ADJUST_GUESTS, SET_GUEST_MINUTES и SaveAttendance отклоняются при увеличении
   количества гостей; сохранение прежних и удаление разрешены.
4. Старое подменю времени, прямые команды длительности и сохранение формы с другим
   временем отклоняются и для администратора. Оплата и выход продолжают работать.
5. Время выключено, гости разрешены: один игрок с гостем + второй игрок,
   оплата вторым 300 ₽ → первый возвращает 200 ₽, равные доли по 100 ₽.
6. Смена настроек сохраняет введённые 90 мин, гостей и оплату открытой тренировки,
   но меняет её правила и версию. Учтённые проводки не меняются; при повторном открытии
   тренировка принимает текущие правила группы.
7. Опрос создан до переключения: итоговая тренировка получает правила при завершении
   сбора. При включённом времени участники по-прежнему начинают с 0 ч.
8. Миграция 7 → 8: опросы, существующие 90 мин / гости / оплата сохраняются;
   оба флага у групп и тренировок true, повторное открытие базы ничего не меняет.

Автоматизация: TrainingRulesTest и прежние проверки платежей, опросов и интерфейса.

## Переключения во время работы

- 30 / 90 мин, гость и 300 ₽: выключить время → равные доли; изменить оплату →
  исходные минуты прежние; включить → снова доли по 30 / 90. SaveAttendance с другой
  длительностью при выключенном времени запрещён, с изменением оплаты разрешён.
- Участник с 0 мин и гостем при равном режиме получает две доли, карточка показывает
  правильные суммы; после включения обе нулевые длительности остаются нулевыми.
- Запретить гостей при наличии двух: они остаются, оплату можно менять, гостей — убрать,
  увеличение запрещено. Включить обратно: можно добавить, прежние данные сохранены.
- Выключить время с открытым подменю: общая карточка и персональная панель обновляются
  без нового сообщения; старое нажатие не меняет данные. Включить: кнопка возвращается.
- Повторить старый запрос «выключить» после обработанного «включить»: повтор не меняет
  новую настройку. Прежняя версия подтверждения учёта отклоняется после смены правил.
- Ошибка записи истории откатывает одновременно настройку, версии и историю тренировок.
  Перезапуск синхронизирует прежние открытые записи один раз без изменения строк участия.
- Учтённый расчёт и отменённая тренировка не меняются до явного открытия / восстановления.
  После открытия прежний расчёт снят, текущие правила приняты, повторный учёт корректен.
- Во время опроса переключить все три флага в обе стороны: poll ID, сообщение и список
  записавшихся те же. Даже с выключенными опросами автор завершает сбор, итоговая
  тренировка получает текущие правила; отказавшиеся отсутствуют.

Автоматизация: TrainingRulesTest и PollFlowTest. Отдельные группы по-прежнему изолированы.

- При равном режиме нельзя сохранить ввод, который делает обратное включение
  времени невозможным из-за переполнения суммы длительностей. Отклонённый ввод
  не меняет состав и минуты; прежний учёт времени включается обратно.

## Рефакторинг: список опросов

На 100 опросах проверить полный проход страниц без пропусков и повторов, фильтр
по автору, назначенного администратора и отсутствие его прав в другой группе.
Проверить выход за первую / последнюю страницу. Число проверок роли не растёт
с количеством опросов; в Kotlin загружается только страница. Навигация и опросы
не читают все аккаунты группы. Проверка закрываемых опросов возвращает EXISTS.
Автоматизация: PollQueryTest; прежние 186 регрессионных тестов сохранены.

## Невидимая персональная панель и переключение опросов

- Четыре раза нажать «Открыть» при имитации принятого, но не доставленного в клиент
  удаления. Отправляется ровно одна панель, повторные нажатия редактируют тот же ID.
  Имитация хранит все отправленные панели по ID и отдельно их видимость, поэтому
  новая отправка не может молча затереть предыдущую.
- Явное отсутствие сообщения в Telegram разрешает новую отправку. Произвольный
  отказ 400 и неопределённый результат редактирования не создают вторую панель.
- После закрытия и открытия новой панели нажать старую кнопку «Присоединиться»:
  участие не записывается, новая панель остаётся открыта.
- Скрытое только клиентом окно может не появиться после принятого редактирования.
  Это ограничение отдельно проверяется в Telegram; доступен личный чат с ботом.
- Повторить для «Завершить сбор»: появляется подтверждение, после подтверждения
  и обработки оставшихся голосов создаётся ровно одна тренировка.
- Открыть тренировку, включить опросы, опубликовать опрос. При включённом,
  выключенном и снова включённом флаге чередовать «Открыть» и «Завершить сбор».
  Обе панели доступны, само открытие не меняет участие и состояние опроса.
- Нажимать кнопки участия и времени внутри панели: её идентификатор не меняется.
- Прервать завершение обработки события после успешной доставки панели, затем
  повторить событие: дополнительная панель не отправляется.

Автоматическая проверка: `PanelVisibilityTest`, дополнительно сценарии
`SelfServiceBotTest`, `PollFlowTest` и `TrainingRulesTest`.

### Навигация подтверждения завершения сбора

В группе проверяется ровно две кнопки: «🏁 Завершить сбор» (`primary`) и
«✖️ Закрыть» (обычный стиль). Закрытие скрывает панель, опрос остаётся открыт,
тренировка не создаётся. В личном чате «Назад» возвращает к описанию опроса.
Эти проверки входят в существующие сценарии `PollFlowTest`.

После подтверждения проверить одну кнопку «Закрыть» в промежуточной панели.
После доставки карточки тренировки панели опроса создателя и администратора
исчезают. Проверить перезапуск перед доставкой, временный отказ удаления
и последующую успешную попытку; панель тренировки другой группы остаётся.

### Актуальная личная карточка опроса

- Голос, смена времени без смены числа участников, второй голос, снятие голоса
  и отказ: количество корректно, идентификатор сообщения сохраняется.
  Неизменное число и повторное обслуживание не вызывают редактирования в Telegram.
- Завершить опрос администратором в группе: в личке создателя тот же экран показывает
  завершение и переход к тренировке; кнопки завершения и ложного «Записались: 0» нет.
- Восстановить старую открытую карточку без сохранённого описания после завершения
  опроса и перезапуска. Используются только активные кнопки текущего сообщения.
- Отказ Telegram при редактировании и перезапуск: обновление повторяется.
- Перейти в меню или удалить карточку: фоновые события не подменяют меню и не создают
  новое сообщение. При выходе пользователя из группы новые данные не доставляются.

Автоматические проверки входят в `PollFlowTest`.

### Администраторы внутри настроек группы

В «Настройках» нет отдельного пункта администраторов. Путь суперадминистратора:
«Настройки групп» → группа → «Администраторы группы». Возврат ведёт в настройки
той же группы. Назначение и снятие прав продолжают действовать только в ней;
назначенный администратор бота не получает права назначать других.

## Изолированное сравнение алгоритмов переводов

Исходная изолированная проверка не меняла рабочий алгоритм; проверки его
последующего внедрения описаны ниже. Задача `settlementBenchmark` с
`-PbenchmarkMode=checks` сверяет точный вариант с независимым полным перебором
малых примеров, проверяет прямые переводы, суммы, ограничение N + 1, нули и
предварительный учёт ожидающего подтверждения перевода. Быстрый собственный
алгоритм проверяется на корректность, но не выдаётся за гарантированно оптимальный.
Подробности и 20-участниковые наборы: [отчёт](experiments/settlements-20/README.md).
Эти экспериментальные проверки запускаются отдельно от обычного `test`.

## Собственный алгоритм в рабочем расчёте

- Точные совпадения устраняют лишнее дробление; принятые 20-участниковые примеры
  совпадают с прототипом, включая известный случай без гарантии абсолютного минимума.
- Прямые положительные переводы обнуляют исходные балансы, не повторяют пары,
  не зависят от порядка строк базы и не меняют входные данные.
- Проверены смешанные балансы 300 случайных групп, нули, 40 участников, суммы у
  пределов Long и суммы положительных остатков, превышающие Long в совокупности.
- Пять участников видят части одной схемы: 700 ₽ нужному получателю и 500/300 ₽
  второму. Старая неправильная пара отвергается. Отметка отправки резервирует сумму,
  подтверждение изменяет баланс; аналогичная тренировка другой группы не затронута.
- Kotlin-перенос сопоставлен с утверждённым прототипом на всех 12 экспериментальных
  наборах. Два интерактивных макета проверены на тех же показательных схемах;
  браузерный сценарий покрывает отправку, подтверждение и изоляцию группы.

Автоматические проверки: `DirectSettlementTest`, `DirectSettlementFlowTest`,
прежние финансовые тесты и `docs/prototype/check-settlement.cjs`.

Страницы баланса проверяются на 20 участниках: 15 на первой, 5 на второй,
слишком большой номер страницы возвращает последнюю. Все ненулевые балансы
сортируются по убыванию, нули следом; порядок не сбрасывается на границе страниц.

Смешанный список из пяти тренировок (две учтённые, две открытые, одна отменённая)
показывает в статистике две, сохраняя все пять в пагинации. Повторное открытие
уменьшает количество/время/оплату; отмена и восстановление в открытую не добавляют
их обратно. Только последующий учёт возвращает тренировку в статистику.
Проверка: `PersonalFlowTest`, интерактивный макет `check-personal-flow.cjs`.

### Старое окно в клиенте без события нажатия

Исчезновение персональных окон после перезапуска Telegram не подтверждает удаление:
проверить, не появились ли они снова. Если нажатия старого окна не поступают через
`getUpdates`, тест обработчика callback не проверяет этот случай. Нужно отдельно
проверять клиент, доставку события и новое открытие; не считать старое окно исправленным
по успешной работе новой панели. Удаление без известного ID ботом не гарантируется.

### Измерение производительности и оставшийся дефект фонового обновления

Отдельная задача `performanceAudit` проверяет нагрузку меню при 1/5/20 известных
группах и изменение оплаты при 1/10/20 персональных панелях. Счётчики SQL и Telegram
отделены от локального времени без сети. Есть контроль с бездействующим соединением
SQLite. Повторяемая методика и результаты — в [отчёте об оптимизации](PERFORMANCE_REVIEW.md).

Сценарий потери ID перенесён в обычные регрессии `PanelVisibilityTest`: общий отказ
фонового редактирования сохраняет ID видимой панели, а следующее открытие её обновляет.
Там же проверяются ограниченная порция, восстановление очереди после перезапуска,
последнее состояние после нового нажатия и отказ одного получателя.
`SelfServiceBotTest` проверяет отзыв прав при тёплом меню, отсутствие лишнего пересчёта
посещаемости, неизменные кнопки и отметки доставок. `ConnectionReuseTest` проверяет
вложенные чтения, откат, закрытие соединений и резервную копию с данными в WAL.
`NavigationMembershipCacheTest` проверяет срок, сброс группы и ограничение размера.
`HttpTelegramApiTest` проверяет исчерпание фонового бюджета до отправки запроса
и независимость следующего пользовательского запроса.

## Единственная группа и возвраты

Покрыто `SingleGroupFlowTest`, а также обновлёнными `PersonalFlowTest` и `PollFlowTest`:

- Одна группа: финансы открываются сразу; промежуточное сообщение выбора не отправляется.
- Две группы участника, администрирование одной: финансы требуют выбора, настройки
  и управление тренировками открывают единственную доступную группу.
- Несколько администрируемых групп: выбор сохраняется, «Назад» возвращает к списку.
- Одна группа: «Назад» из настроек возвращает к личным настройкам, из опросов — в меню.
- Ноль групп: пустой список с объяснением, публикации не происходит.
- Создание при одной группе: сразу проверка с названием группы, создание только
  по «Опубликовать». При добавлении второй группы «Назад» показывает список;
  после потери членства в ней возврат пропускает список.
- Для опроса учитывается флаг группы: при единственной подходящей группе «Назад»
  с проверки ведёт к четвёртому варианту; отмена не публикует опрос.
- Потеря членства или роли после открытия меню блокирует автоматический вход,
  даже если список групп ещё в кэше. Потеря прав бота/членства до публикации
  блокирует создание из уже подготовленной формы.

## Согласованный финансовый интерфейс: реализация

`FinanceFlowTest` проходит реальные обработчики обновлений с SQLite и имитацией Telegram:

- Меню, единая форма, рекомендация при любом пути входа, неизменная структура
  кнопок при ±, свободный ввод без самовольного округления, нулевая сумма.
- Число обновляет ту же карточку, не создаёт перевод. Неверный текст сохраняет
  сумму. После восстановления рекомендации сумма остаётся видимой.
- Подтверждение и повтор события учитываются один раз. Отмена ожидания отправителем
  освобождает резерв; чужой участник и подтверждённый отправитель отменить не могут.
- Администратор меняет подтверждённую сумму и отменяет её: корректные проводки,
  отметка автора. Правка ожидания не подтверждает, отменённого не восстанавливает.
- Отозванные права блокируют старые кнопки и незавершённый ввод суммы.
- Все участники читают «Мои / Все» только своей группы, по 10; возвраты сохраняют
  режим и страницу. Балансы / получатели по 15, профили и перевод разделены.
- Изменение суммы выполняет один `editRich`, не отправляет нового сообщения и
  не делает сетевых запросов по числу участников. SQL ограничен на группу из 20.
- «Мои тренировки»: время пользователя без гостя; новой загрузки для колонки нет.
  У отменённой тренировки ячейка пустая, ранее введённое время сохранено в базе.

`PaymentCorrectionTest`: права в сервисе независимо от интерфейса, повтор запроса,
устаревшие версии, отрицательные суммы, отзыв членства, переполнение резерва,
конкурирующие отмена и подтверждение, целостность журнала и базы. История одним
SELECT вместо SELECT на строку; размер страницы 10, баланса 15.
`FinanceServiceTest` сохраняет проверки следующих тренировок, ожидающих переводов,
изоляции и резервирования. Старые проверки закрытого общего просмотра заменены
сценариями общего чтения при отдельных правах изменения.

Макет: `node docs/prototype/check-finance-amounts.cjs` проверяет чистые функции.
Это не визуальная проверка клиента Telegram. Измерения без сети не гарантируют
время от нажатия до обновления у пользователя.

Контраст личной суммы: активные `danger` / `success`, без `disabled`; нажатие
сохраняет сообщение и финансовые записи. Проверка в `FinanceFlowTest`.

`FinanceFlowTest` также проверяет заголовок финансового меню и разделение
заголовка / суммы / пояснения в rich HTML; число сетевых обновлений не увеличено.

Общая таблица: столбца «Перевод» и плюсов нет. Профиль и баланс имеют отдельные
действия; ноль открывает свободную сумму, ± не включают округление. Подсказка
объясняет оба нажатия. Проверяется в `FinanceFlowTest`.

`PollNavigationTest`: пустой пункт скрыт, чужие опросы не дают обычному участнику
новую группу, административные права отдельны по группам. Одна подходящая группа
пропускает выбор и при входе, и при возврате; две предлагают выбор. После завершения
одного сбора ненужная группа исчезает из выбора.

`PaymentCorrectionTest`: чужой аккаунт и отрицательная проверка членства не
попадают в список; старые отсутствующие записи без активности скрыты, реальные
финансовые связи сохраняются. `FinanceFlowTest`: история без кнопок записей,
профили по именам и детали по ячейкам, права и исходная страница сохранены.

`FinanceFlowTest`: участники чата без тренировок отсутствуют в балансе группы,
но доступны как получатели собственного перевода. Признак участия привязан
к группе; чужая тренировка не добавляет человека в её баланс.

`FinanceFlowTest`: «Проверить поступления» не содержит числа; без входящих отключена
и не имеет callback, с входящими активна и зелёная. После подтверждения последнего
перевода повторный показ финансов отключает кнопку. Другая группа остаётся пустой.
Функция макета проверяется без браузера в `check-finance-amounts.cjs`.

`FinanceFlowTest`: ручной ввод не создаёт перевод и не удаляет текущую карточку;
число над кнопками, исходное сообщение удаляется фоном. Временный отказ удаления
сохраняет сумму и очередь, следующая попытка удаляет только ввод. Колонка времени
выравнивается вправо; новая подпись предложения сохраняет прежнее действие.

`FinanceFlowTest`: нажатие ненулевого баланса открывает получателя с пустой
суммой; подтверждение отключено. Явный выбор предложения подставляет сумму,
вход через готовый перевод сохраняет исходный расчёт.

`FinanceFlowTest`: отправитель меняет100→150 ₽ до подтверждения, ожидание
сохраняется, история указывает отправителя. Получатель по старой карточке100 ₽
не может подтвердить150 ₽; новая карточка подтверждает правильную сумму. После
подтверждения у отправителя нет правки/отмены. Проверены и чистые функции макета.
