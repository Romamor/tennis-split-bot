# Просмотр базы

Подготовлена проверенная копия рабочей SQLite на 8 сентября 2026 года:
`data/inspection/bot-20260908.sqlite`. Она находится только на Mac,
исключена из Git и имеет права 600. Это снимок: последующие действия
в Telegram не появляются в нём автоматически.

В терминале Mac открыть:

```sh
sqlite3 -readonly -header -column /path/to/tennis-split-bot
```

Внутри SQLite:

```sql
.tables
.schema participants
SELECT display_name, active FROM participants;
```

`active = 1` — ходит, `active = 0` — не ходит. Чтобы выйти, ввести `.quit`.
Для просмотра через графический клиент открыть тот же файл как SQLite;
доступность такого клиента на этом компьютере отдельно не проверялась.

Готовые примеры находятся в [inspect.sql](inspect.sql). Выполнить их все:

```text
.read /path/to/tennis-split-bot
```

| Таблица | Что смотреть |
| --- | --- |
| participants | Имена, активность, привязка Telegram |
| training_drafts | Тренировки, статус, рабочая и учтённая версии |
| operations | Финансовые операции, исправления и возвраты |
| balance_entries | Изменения балансов; суммой получается текущий баланс |
| workflow_audit | Полный журнал правок, включая черновики и участников |
| tg_groups | Соответствие расчётных групп чатам Telegram |

`content_json` — рабочая версия тренировки; `published_json` — последняя
учтённая версия. При статусе EDITING в балансах действует опубликованный
вариант, при CANCELLED его вклад уже отменён.

Все семь примеров SELECT проверены на копии. Проверки целостности SQLite
и внешних ключей успешны. Запуск через `-readonly` защищает сам снимок
от случайных изменений; подключение к рабочей базе для этих запросов не нужно.

После обновления рабочей базы до схемы 4 добавилась таблица `tg_editors`:
личные формы, ещё не сохранённые как общий черновик. Старый локальный
снимок `bot-20260908.sqlite` был сделан до этого обновления и остаётся
в схеме 3. Готовые запросы к участникам, тренировкам и деньгам работают
в обеих версиях.
