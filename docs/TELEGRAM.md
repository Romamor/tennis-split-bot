# Первый запуск Telegram-бота

Разделы 1–2 описывают создание собственного бота и локальный запуск.
После настройки можно перейти к подключению группы. Имена рабочих ботов,
адреса серверов и токены не публикуются. [Размещение](../deploy/README.md).

## 1. Создать аккаунт бота

1. Открыть официальный [@BotFather](https://t.me/BotFather).
2. Отправить `/newbot` и пройти выбор имени и имени пользователя.
3. Полученный токен вставить в `TELEGRAM_BOT_TOKEN` в локальном файле `.env` в корне проекта.

Токен не нужно отправлять в этот разговор или указывать в команде терминала.
Для новой установки скопировать `.env.example` в `.env` и установить права
`chmod 600 .env`. Для существующего бота файл уже заполнен — не заменять его.
`.env` исключён из контроля версий. Настройки считываются как данные, без
выполнения команд оболочки. Официальная инструкция:
[создание бота и получение токена](https://core.telegram.org/bots/tutorial).

Пример остальных настроек есть в `.env.example`:

| Настройка | По умолчанию |
| --- | --- |
| `BOT_DATABASE_PATH` | `data/bot.sqlite` — отдельная рабочая база |
| `BOT_TIME_ZONE` | `Europe/Moscow` — для новых групп |
| `BOT_POLL_TIMEOUT` | `25` секунд |

Переменные окружения имеют приоритет над `.env`. Данные демонстраций находятся в других файлах и в рабочую базу не переносятся.

## 2. Запустить процесс

Из папки проекта:

```sh
./scripts/gradle.sh run --args=bot
```

Процесс работает, пока открыт терминал и компьютер не спит. Остановка — `Ctrl+C`. Перезапуск с тем же файлом базы сохраняет участников, балансы, незавершённые диалоги и результаты команд.

Для запуска собранного пакета с настроенной Java 21:

```sh
./scripts/gradle.sh installDist
./build/install/tennis-settlements-bot/bin/tennis-settlements-bot bot
```

На компьютере без настроенного `JAVA_HOME` удобнее первая команда через `scripts/gradle.sh`: она находит Java из IntelliJ IDEA. Запускать нужно один экземпляр. Блокировка файла предотвращает два локальных процесса с одной базой; один и тот же токен также не следует запускать одновременно на разных компьютерах.

Публичный сервер HTTP и входящий порт не нужны: процесс получает обновления
через длительный опрос `getUpdates`. На VDS уже настроен автоматический
перезапуск контейнера. Пока он работает, локальный экземпляр с тем же токеном
запускать не следует. Расписание резервного копирования ещё не настроено.

## 3. Подключить группу

1. Открыть личную переписку с новым ботом и нажать «Старт».
2. Добавить бота в группу и назначить администратором. Администраторская роль нужна для надёжной проверки текущего членства через `getChatMember`; закрепление сообщения выполняет человек. Бот не использует функции удаления сообщений, назначения администраторов Telegram или управления участниками. [Ограничение Telegram API](https://core.telegram.org/bots/api#getchatmember).
3. От своего имени администратора группы отправить `/setup`. Если в чате несколько ботов, использовать `/setup@имя_бота`. Анонимный режим администратора для этого действия не подходит: нужен реальный отправитель команды.
4. Закрепить появившееся меню вручную.
5. Нажать кнопку «Открыть меню» в сообщении бота именно в этой группе. В личном меню открыть «Ещё → Участники», добавить записи и выбрать «Это я» у своей записи. Остальные могут связаться позже; непривязанные участники уже участвуют в расчётах.

Первый настраивающий администратор становится организатором расчётов. Дополнительных организаторов он назначает через профиль участника. Повторный `/setup` обновляет существующее общее меню.

Администратор-бот технически получает обычные сообщения группы. Код игнорирует их содержимое; в базу не записывается текст общей переписки. Обрабатываются `/setup`, `/restore`, служебный переход группы в супергруппу, личные сообщения и нажатия кнопок.

## Как пользоваться

- В общем чате — одно меню и одна карточка на учтённую тренировку. Все поля заполняются в личной переписке.
- Главное меню: «Записать тренировку», «Кто кому должен», «Записать перевод». История, участники, балансы и незавершённые тренировки находятся в «Ещё».
- В заголовке экранов и запросов ввода указана выбранная группа. «Сменить группу» или `/groups` показывает доступные группы, которые пользователь уже открывал или настраивал; членство проверяется заново. Для впервые открываемой группы нужно нажать кнопку бота в её общем чате. `/menu` продолжает последнюю выбранную группу.
- «Ещё → Тренировки» показывает незавершённые записи; «Показать все» открывает и завершённые. Оба списка объединяют личный ввод и общие записи без дублей, по 8 на страницу. Создание тренировки находится только в главном меню.
- «Записать тренировку» открывает выбор игроков: по 12 человек, две колонки. Сверху частые участники учтённых тренировок **этой группы**. Черновики и отменённые тренировки в частоту не входят. Выбор сохраняет порядок списка; новому игроку назначается 1 ч. «Дальше: оплаты» сразу открывает ввод оплат.
- «Время и +1» позволяет изменить длительность и добавить гостя. Время выбирается с шагом полчаса; гость показан вместе с пригласившим. В «Ещё» находятся выбор всех, снятие всего выбора, неактивные игроки, добавление человека и повтор состава с явно указанной датой последней учтённой тренировки этой группы.
- В оплатах видны состав и общая сумма. Сначала предлагаются выбранные игроки и уже оплатившие; «Оплатил другой человек» открывает остальных. Повторный ввод заменяет сумму, ноль убирает оплату. После ответа сохраняется страница списка.
- «Записать тренировку» доступна прямо на экране оплат, когда выбраны игроки и есть оплата. Дополнительный просмотр расчёта не обязателен. Первичный учёт выполняет создатель или организатор. Исправления **уже учтённой** тренировки может сохранить любой текущий участник её группы, даже если сам не играл. Автор правки остаётся в истории; чужая версия не затирается молча. Отмена тренировки остаётся доступна создателю или организатору.
- «Ещё → Сохранить на потом» явно сохраняет общий черновик без изменения долгов. До этого ввод хранится только для автора и переживает перезапуск. В «Ещё» также находятся дата, необязательный расчёт и закрытие без сохранения.
- «Записать перевод» принимает аванс, частичный или полный возврат. Перед записью показываются стороны, сумма и дата. Похожий перевод требует отдельного подтверждения.
- «Уточнить перевод» предлагает временно не учитывать запись. Завершает уточнение его инициатор через «Всё верно» либо отмену ошибочной записи.
- «Балансы» и «Участники» по умолчанию показывают тех, кто ходит, в порядке посещаемости. «Не ходят» открывает отдельный список; незакрытые расчёты неактивных обозначены и продолжают участвовать в общем расчёте.
- «История» показывает до 8 коротких кнопок с типом записи, датой, суммой и состоянием. Текст сообщения не дублирует эти записи; подробности открываются нажатием. Внутри записи есть «Изменения записи», а «Все изменения» открывает полный журнал, включая участников и настройки. Ни одна правка не удаляется. Неактивные участники остаются в балансах и взаимозачёте.

При запросе имени, суммы, времени или даты нужно **ответить на конкретное сообщение-запрос бота**. Это защищает от записи ответа в другую тренировку после переключения раздела. Выйти к меню можно через `/menu`; выход не удаляет общий черновик. После текстового ответа и `/menu` актуальный экран появляется внизу переписки. При нажатии кнопок текущий экран обновляется на месте. Старые кнопки убираются после подтверждённой отправки нового экрана.

## Проверка доступа и повторов

Ссылка из группы сама по себе не даёт доступа. Перед действием адаптер проверяет членство пользователя и администраторскую роль бота. Кнопки содержат короткие случайные идентификаторы; команды и ожидаемые версии хранятся в базе и привязаны к конкретному пользователю.

Планы обработки текстовых ответов сохраняются до изменения финансовых данных. Повторное получение обновления или нажатие той же кнопки не создаёт повторный перевод. После перезапуска сохраняются номер обработанного обновления, планы, диалоги и запросы ввода.

Если проверка членства временно недоступна, действие не выполняется до успешной проверки. Если Telegram явно отказывает в доступе, бот не показывает данные группы. Токен отсутствует в сообщениях ошибок HTTP-клиента и не хранится в базе.

## Если карточка или уведомление не доставлены

Для новой отправки сначала сохраняется намерение. При неизвестном результате бот не отправляет общую карточку повторно автоматически. Незавершённые отправки после перезапуска также переходят в состояние, требующее проверки.

- **Карточка уже есть:** ответить на неё в группе командой `/restore`. Бот проверит автора карточки, её ссылку и права на восстановление, запомнит номер сообщения и обновит его.
- **Карточки нет:** в личном меню организатора открыть «Ещё» → «Восстановить сообщение в группе», выбрать запись и подтвердить отсутствие карточки. Повторное нажатие этой же кнопки не создаст ещё одну копию.
- **Личное уведомление не доставлено:** перевод остаётся в расчётах, а в его подробностях появляется отметка. Уведомление не переносится в общий чат. Участнику стоит открыть личную переписку с ботом; историю можно посмотреть по запросу.

Правки существующей карточки повторяются безопасно. Карточка отражает последний учтённый вариант, даже если кто-то уже готовит новые рабочие правки. При переходе группы в супергруппу сохраняется внутренний идентификатор расчётов; прежним карточкам может потребоваться восстановление.

## Код и данные

| Компонент | Назначение |
| --- | --- |
| `TelegramApi.kt` | Типы API и HTTP-клиент на Java HttpClient |
| `TelegramBot.kt` | Проверенные действия, ответы на запросы и защита от повторов |
| `BotUi.kt` | Тексты и кнопки личных экранов |
| `TelegramDelivery.kt` | Членство, общие карточки, личные уведомления и восстановление |
| `TelegramStore.kt` | Диалоги, короткие ссылки, кнопки, планы и результаты отправок |
| `BotRuntime.kt` | Настройки, блокировка процесса и длительный опрос |

Схема базы 3 добавляет таблицы `tg_*`. Ранее накопленные расчёты сохраняются. База привязана к ID одного бота: другой аккаунт бота не сможет случайно продолжить её сеансы. Резервная копия включает и финансовое, и диалоговое состояние; токен хранится отдельно.

## Что проверено и что осталось

Локально прошли 113 тестов, полная сборка и подготовка запускаемого пакета. Проверены полные диалоги, изменяющаяся карточка, выбор времени в часах с шагом полчаса и перенос личного меню вниз, тёзки, повторные кнопки, устаревшие ответы, запрет чужих кнопок, выход из группы, ошибки членства, личные уведомления, уточнения и восстановление после неопределённой отправки.

Живой запуск, работа конкретных клиентов Telegram и поведение реального API при обрыве соединения пока не проверены. Следующий шаг — создать бота через @BotFather, заполнить `.env`, провести пробную тренировку в небольшой группе и проверить её расчёт. После этого выбрать постоянное размещение и расписание резервных копий. Политика списания долгов ушедших участников остаётся открытой.

## Ограничение длины списков

Растущие списки имеют страницы: участники и балансы, выбранные игроки, оплаты, предложения переводов, стороны перевода, тренировки, история, журнал изменений, группы, похожие переводы и восстановление сообщений. Обычно на странице 8 записей; выбор игроков — 12 в двух колонках. В подробностях исторической правки показываются по 4 игрока и 4 оплаты для каждой версии с отдельным перелистыванием. Краткие карточки в общем чате ведут к полным спискам в личной переписке.

Пагинация ограничивает размер интерфейса. Часть запросов пока загружает историю группы целиком и выбирает страницу в Kotlin; перенос выборки страниц в SQL остаётся предложением из ревью базы.

Кнопки актуального личного меню не устаревают со временем. После подтверждённой замены экрана старый набор удаляется через 2 минуты с учётом интервала очистки. Ожидаемый текстовый ответ и незавершённое сохранение защищены. Постоянные ссылки закреплённого меню группы не удаляются. После установки этой версии нужно один раз открыть `/menu`: совместимость с прежними тестовыми экранами не сохраняется.
