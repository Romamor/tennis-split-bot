# Документация

По требованию владельца проекта любые изменения сопровождать актуализацией
соответствующей документации в том же наборе правок.

- Поведение и доступные действия описывать в README.md.
- Переходы и состояния интерфейса отражать в docs/UI_FLOW_REVIEW.md.
- Новые регрессионные сценарии добавлять в docs/UI_REGRESSION_SCENARIOS.md.
- Изменения базы отражать в описании таблиц и связей; эксплуатационные изменения —
  в документации размещения, хранения и резервного копирования.
- В docs/DEPLOYMENT_STATUS.md различать подготовленное локально и установленное
  на сервере. Не отмечать выкладку завершённой до проверки работающей версии.

# Публичный репозиторий

Репозиторий публичный. Не добавлять токены, пароли, ключи, реальные адреса серверов,
имена рабочих ботов, идентификаторы пользователей/чатов, домашние пути владельца,
состав сторонних служб и подробные журналы эксплуатации. Такие сведения хранить
вне Git; локальные заметки допустимы в игнорируемом data/private-docs с закрытыми правами.
Публичные документы содержат общие инструкции, схему приложения и искусственные примеры.
Перед коммитом проверять весь набор изменений, а не полагаться только на .gitignore.

Документацию о личных сторонних службах владельца и их мониторинге,
не относящихся к работе бота, хранить только в data/private-docs. Не публиковать
её на GitHub даже без адресов и ключей. Для этих изменений требование обновлять
документацию выполняется в закрытых локальных заметках.
