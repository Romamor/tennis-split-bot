# Размещение на сервере

Один контейнер с Java 21, Kotlin и SQLite. Публичные порты не открываются:
бот сам обращается к Telegram методом long polling. Контейнер ограничен
256 МБ оперативной памяти и дополнительно до 128 МБ swap; максимальная
куча Java — 96 МБ. Он работает под UID 10001 и автоматически перезапускается.
Каталог `/opt/tennis-split-bot/data` сохраняется при пересоздании контейнера.
Токен хранится отдельно в `bot.env` и не включается в образ или Git.
Служба Docker, другие контейнеры, их сети, порты и данные не меняются.

## Подготовка

На Mac собрать отдельный каталог поставки (путь должен быть новым):

```sh
sh deploy/build.sh /private/tmp/tennis-split-release
```

Скрипт запускает сборку и тесты, копирует только дистрибутив и файлы установки.
В поставке зависимости находятся в app/lib, а JAR приложения — в app/tennis-settlements-bot.jar.
Dockerfile собирает обычный runtime /app/lib, но зависимости и приложение попадают
в разные слои. Обновление кода не создаёт новую копию всех библиотек в каждом образе.
Существующий SSH-ключ GitHub задаётся локально через `core.sshCommand`,
личные пути и сами ключи в репозиторий не входят.

На сервер передать каталог поставки через SSH и отдельно скопировать
локальный `.env` как `bot.env` в этот каталог. Каталог должен иметь права
700, файл `bot.env` — 600. Не вставлять токен в команды или переписку.
Первая установка создаёт новую пустую базу; локальные демонстрационные
данные автоматически не переносятся. Не запускать одновременно два
экземпляра с одним токеном даже при разных базах.

## Первая установка

После просмотра файлов поставки выполнить на сервере:

```sh
sudo sh ~/tennis-split-release/install.sh
```

Пароль sudo вводится в своём терминале. Установщик проверяет доступ
к Docker и публичному Telegram API, создаёт `/opt/tennis-split-bot`,
собирает образ и запускает только проект `tennis-split-bot`.
Если каталог установки уже существует, скрипт останавливается без изменений.
Если первая установка прервана после создания каталога, сначала выяснить
причину и продолжить нужный шаг вручную; повторный запуск не затирает данные.

## Проверка и остановка

```sh
sudo docker --context default compose -f /opt/tennis-split-bot/compose.yaml ps
sudo docker --context default compose -f /opt/tennis-split-bot/compose.yaml logs --tail 30 bot
sudo docker --context default compose -f /opt/tennis-split-bot/compose.yaml stop bot
```

Статус контейнера `running` ещё не подтверждает работу Telegram. В журнале
должно появиться «Бот @… запущен», после чего вручную проверить `/start`
в личном чате и `/start` в тестовой группе по [инструкции](../docs/TELEGRAM.md).
Остановка сохраняет базу. Не использовать очистку Docker или удаление данных.

## Копия базы и обновление

Сделать согласованную копию работающей SQLite через встроенную команду,
указав новое имя файла при каждом запуске:

```sh
sudo docker --context default compose -f /opt/tennis-split-bot/compose.yaml exec bot /app/bin/tennis-settlements-bot backup /data/settlements.sqlite /data/backup-YYYY-MM-DD.sqlite
```

Перед обновлением сохранить копию вне сервера и проверить её командой
`verify`. Остановить только `bot`, заменить `app/` и Dockerfile из одного нового пакета, собрать
образ и выполнить `up -d bot`, сохраняя `data/` и `bot.env`.
Автоматическое обновление и вынос резервных копий пока не настроены.
Возврат старого образа после будущей миграции базы может потребовать
восстановления совместимой копии.

Команды backup/verify в подготовленной версии не мигрируют источник. Подробности
и сравнение способов: [BACKUPS.md](../docs/BACKUPS.md). Оценка роста и предложения
по очистке: [STORAGE_REVIEW.md](../docs/STORAGE_REVIEW.md). Очистка не выполняется
скриптами установки автоматически.
