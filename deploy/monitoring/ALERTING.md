# Уведомления о памяти

Статус: предлагаемые правила. Панель показывает значения — это подтвердил пользователь.
Выбрана доставка владельцу в личный Telegram через отдельного бота.
Правила и доставка уведомлений ещё не настроены и не проверены. Отдельного
сервисного ключа Grafana для управления правилами у сборщика нет: его облачный
ключ используется только для передачи метрик.

## Условия

Оценивать раз в минуту. Первые два условия должны сохраняться пять минут,
чтобы кратковременный скачок не создавал уведомление. При восстановлении отправлять
сообщение о завершении проблемы. Повтор продолжающейся проблемы — не чаще раза в час.
Это начальные настройки, которые можно уточнить после наблюдения реальной истории.

| Правило | Условие | Ожидание перед уведомлением |
| --- | --- | --- |
| Мало доступной памяти | MemAvailable меньше 100 МиБ | 5 минут |
| VMware удерживает много памяти | Ballooning больше 50% общей RAM | 5 минут |
| Метрики Linux не поступают | Нет показателя памяти за последние 3 минуты | 1 минута |
| Дополнительные метрики устарели | Сборщик VMware / контейнера не обновлялся более 3 минут | 1 минута |

Последнее правило нужно, потому что Alloy может продолжать отправлять старый
файл дополнительных метрик после остановки его таймера. Возраст определяется
по содержимому `vds_extra_sample_timestamp_seconds`, а не по времени отправки файла.

## Запросы для правил Grafana-managed

Для каждого правила выбрать тот же Prometheus-источник, что и в панели.
Запросы используют фиксированный instance: переменные панелей `$instance`
в правилах уведомлений не подставляются.

**Мало доступной памяти:** условие Last IS BELOW 100.

```promql
node_memory_MemAvailable_bytes{instance="vds-1",job="integrations/node_exporter"} / 1024 / 1024
```

**VMware удерживает много памяти:** Last IS ABOVE 50.

```promql
100 * vds_balloon_current_bytes{instance="vds-1",job="integrations/node_exporter"}
/ node_memory_MemTotal_bytes{instance="vds-1",job="integrations/node_exporter"}
```

**Метрики Linux не поступают:** Last IS ABOVE 0.5.

```promql
max(absent_over_time(node_memory_MemAvailable_bytes{instance="vds-1",job="integrations/node_exporter"}[3m])) or vector(0)
```

**Дополнительные метрики устарели:** Last IS ABOVE 180.

```promql
(time() - max(vds_extra_sample_timestamp_seconds{instance="vds-1",job="integrations/node_exporter"})) or vector(9999)
```

При отсутствии данных первых двух правил оставить состояние **No Data**,
при ошибке запроса — **Error**. Такие состояния тоже должны доходить до выбранного
получателя. Не превращать отсутствующие показания памяти в ноль: это другая проблема.

## Настройка и проверка

1. Создать получателя в Alerting → Notification configuration → Contact points.
2. Выполнить Test и проверить, что сообщение действительно получено.
3. Создать правила через Alerts & IRM → Alert rules → New alert rule, выбрать
   источник, запрос, условие, папку и группу оценки с интервалом 1 минута.
4. В Preview проверить реальные значения; затем выбрать получателя и сохранить.
5. Проверить прохождение временного тестового правила через Pending → Alerting
   и доставку сообщения о восстановлении. Для этого не нужно занимать память
   сервера или останавливать бота. Тестовое правило должно быть явно отделено
   от рабочих; после проверки его можно приостановить.

Само сохранение правил не подтверждает доставку. Тест контакта проверяет только
канал уведомлений; отдельное тестовое правило проверяет всю цепочку оценки.

Источники: [правила Grafana](https://grafana.com/docs/grafana/latest/alerting/alerting-rules/create-grafana-managed-rule/),
[получатель Telegram](https://grafana.com/docs/grafana/latest/alerting/configure-notifications/manage-contact-points/integrations/configure-telegram/).

## Личный Telegram

1. Через официальный @BotFather создать отдельного бота командой `/newbot`.
2. Открыть личный чат с созданным ботом и отправить `/start`.
3. Токен сохранить в закрытом файле вне Git. Chat ID получить через API именно
   этого бота после начала диалога; не публиковать полный ответ `getUpdates`.
4. В Grafana создать Contact point типа Telegram и указать токен / Chat ID.
   Проверить Test и оставить включёнными сообщения о восстановлении.

В группу бота добавлять не нужно; администраторских прав не требуется.
Отдельный процесс бота не запускается: сообщения отправляет Grafana.
Токен теннисного бота для этой интеграции не используется.
