# Tennis Split Bot

Telegram-бот для взаиморасчётов в постоянной группе с меняющимся составом тренировок.
Kotlin, Java 21 и SQLite; один процесс получает события Telegram через long polling.
Бот учитывает расходы и реальные переводы, но не принимает и не переводит деньги сам.

Репозиторий публичный. Рабочие настройки и данные хранятся отдельно:
[правила безопасности](SECURITY.md).

Новая версия реализована на отдельной нормализованной схеме. Статус установки:
[DEPLOYMENT_STATUS.md](docs/DEPLOYMENT_STATUS.md).

[Сверка замечаний к первой версии со второй](docs/V1_TO_V2_REVIEW.md):
сохранённые требования, регрессии, отложенные функции и предложение интеграционных проверок.

## Подключить бота к группе

Если бот уже работает на сервере, для подключения ещё одной группы не нужны
новый токен или отдельный запуск программы.

1. В Telegram открыть группу → нажать её название → «Добавить участников»
   и найти бота по его `@username`.
2. Открыть настройки группы → «Администраторы» → «Добавить администратора»
   и выбрать бота. Названия пунктов могут немного отличаться между клиентами Telegram.
3. Включить право **«Закрепление сообщений»**. Остальные дополнительные права
   для работы бота не требуются — их можно отключить, как указано ниже.
4. **Отправить `/start` именно в группе**, от своего аккаунта, не анонимно.
   Если в группе несколько ботов, явно адресовать команду: `/start@username_бота`,
   подставив настоящий username. `/menu` в группе поддерживается и открывает то же меню;
   при первом подключении используйте `/start`. Команда `/setup` относится к старой версии.
5. Бот автоматически закрепит стартовое меню **без уведомления участников**.
   В сообщении бота нажать **«Открыть меню»**. В личном чате нажать «Старт»,
   если Telegram его предлагает. Теперь можно создать тренировку и выбрать эту группу.

Стартовое меню остаётся в закрепе независимо от тренировок. Завершение или отмена
снимает закреп только с карточки соответствующей тренировки. Повторные `/start`
и `/menu` обновляют то же меню и восстанавливают его закреп, если его сняли вручную.
Если сообщение удалили, бот создаст и закрепит новое. Если закрепление было отклонено
из-за прав, включить «Закрепление сообщений» и повторить `/start` в группе.

### Зачем боту администраторская роль

Она нужна для проверки доступа и работы с закреплёнными карточками:

- **Проверка членства в конкретной группе.** Бот проверяет, что нажавший кнопку
  по-прежнему состоит в этой группе, и определяет его роль. Поэтому старая ссылка
  не даёт доступа человеку, вышедшему из чата. Telegram гарантирует работу
  `getChatMember` для других пользователей только когда бот — администратор.
  [Ограничение Telegram API](https://core.telegram.org/bots/api#getchatmember).
- **Закрепление стартового меню и открытой тренировки; снятие закрепа тренировки после учёта или отмены.**
  Для этого используется право `can_pin_messages` — «Закрепление сообщений».
  [Закрепление](https://core.telegram.org/bots/api#pinchatmessage),
  [снятие закрепа](https://core.telegram.org/bots/api#unpinchatmessage).

| Дополнительное право Telegram | Что выбрать для бота |
| --- | --- |
| Закрепление сообщений | Включить |
| Удаление чужих сообщений | Можно отключить |
| Блокировка / ограничение участников | Можно отключить |
| Приглашение участников | Можно отключить |
| Назначение администраторов | Можно отключить |
| Изменение информации группы | Можно отключить |
| Управление темами, видеочатами, историями | Можно отключить |

Сам статус администратора даёт боту более широкую видимость сообщений группы.
Текущий код игнорирует обычную переписку и не сохраняет её текст в базе:
обрабатывает команды, нажатия и служебные события членства. Бот удаляет свои
устаревшие меню и скрывает персональные панели; для этого не нужно разрешение
на удаление чужих сообщений.

**«Администратор бота» внутри приложения — другая роль.** Назначение через
«Настройки» → «Администраторы групп» даёт человеку права управления тренировками
в выбранной группе, но не делает его администратором Telegram-чата.

## Как пользоваться

1. [Подключить бота к группе](#подключить-бота-к-группе): назначить администратором
   с правом закрепления сообщений и отправить `/start` в группе.
2. Через «Открыть меню» перейти в личный чат. `/start` открывает общее меню пользователя,
   без предварительного выбора группы и без её названия в тексте меню.
3. «➕ Создать тренировку»: **Название → Дата → Время → Группа → Проверка**.
   На первом шаге есть кнопка с личным названием по умолчанию. Дату меняют стрелки
   дня / месяца / года, время — стрелки часов (шаг 1 час) и минут (шаг 30 минут).
   Группу выбирают последней: видны известные боту группы, в которых состоит
   пользователь, а бот имеет права администратора. Условия повторно проверяются
   перед публикацией. В каждом шаге «Назад» / «Отмена» стоят в одном ряду, на первом
   только «Отмена». Назад сохраняет ввод; отмена сразу возвращает в главное меню.
   На проверке — «Опубликовать», ниже «Назад» / «Отмена». Публикация создаёт одну
   карточку в выбранной группе и запрашивает закрепление с уведомлением.
4. Нажать «Открыть»: появится персональная карточка с той же таблицей и личными
   кнопками. Само открытие ещё не записывает участие. «Присоединиться» записывает
   0 ч и 0 ₽. Время меняется на ±0,5 ч и ±1 ч, оплата — на ±5, ±50 и ±100 ₽.
   Каждое изменение сохраняется сразу, обновляя общую и открытые персональные карточки.
5. Кнопка «Добавить гостя» на основной панели сразу добавляет гостя;
   рядом появляется «Убрать гостя». Можно добавить до 99 гостей. Каждый играет
   столько же, сколько пригласивший. При изменении его времени меняется время гостей.
6. «Не участвую» удаляет участника из тренировки вместе с оплатой, временем и
   гостями. Строка исчезает из таблицы. При повторном присоединении — 0 ч и 0 ₽,
   без гостей. Отдельные переводы между людьми и история изменений сохраняются.
   «Закрыть» только скрывает панель.
7. Создатель тренировки или администратор этой группы проверяет карточку и выбирает «Изменить статус» → «Завершена». После этого она
   влияет на балансы, карточка снимается с закрепа, а персональные панели всех
   участников закрываются. При отмене карточка тоже снимается с закрепа; само
   сообщение остаётся в чате. Восстановление не закрепляет её автоматически.
   Создатель или администратор выбирает «Изменить статус» → «Открыта»: прежний расчёт сразу отменяется. После правок требуется повторный учёт.

Карточка содержит название, дату и начало, затем таблицу «Участник / Время / Оплата /
Баланс». Отдельного блока с названием группы нет. Имена ведут на профили Telegram,
гости показаны как «Имя гость 1», «Имя гость 2». Пустой состав: «Пока никто не зарегался».
Баланс в таблице — результат этой тренировки: оплата минус доля расходов. Доли гостей
показаны отдельно, но в расчётах группы относятся к пригласившему. До учёта это
предварительный расчёт; если оплаты уже есть, а время ещё не указано, показано «—».
В открытой карточке под таблицей нет отдельного поясняющего блока.

Таблицы используют rich messages Telegram, персональные панели — ephemeral messages.
Одна панель на человека и группу обновляется на месте; исчезнувшая открывается заново.
В общей карточке одна строка с единственной кнопкой «Открыть». Такая клавиатура
позволяет Telegram показывать действие в полосе закрепа.
В основной персональной панели создатель и администраторы этой группы видят
«Редактировать». В подменю времени и оплаты, а также при управлении другим игроком
этой кнопки нет. Права повторно проверяются при нажатии и при входе в личный
редактор; отозванные права дают ошибку с «ОК» без перехода и нового сообщения.
Учтённую или отменённую тренировку можно открыть для редактирования через её
карточку в «Моих тренировках» либо через «Управление тренировками» у администратора.
Для учтённой и отменённой тренировки «Открыть» недоступно всем, включая администраторов:
появляется окно с «ОК» и текстом «Тренировка завершена» / «Тренировка отменена».
Старые кнопки времени, оплаты, гостей и переходов тоже отклоняются без изменения данных.
Если клиент не показывает персональную панель, можно открыть личный чат с ботом →
«Мои тренировки» → тренировку → «Открыть». Промежуточные сообщения в группу
не отправляются. [Схема переходов](docs/UI_FLOW_REVIEW.md).

Создатель или администратор открывает редактор со стандартной карточкой сверху:

- «Изменить статус»: для открытой доступны «Отменена» и «Завершена», для остальных — только «Открыта».
- «Изменить название и время»: название, дата и начало открытой тренировки.
- «Добавить игрока» / «Исключить игрока» в одном ряду. Нажатие имени сразу меняет состав, кнопка исчезает.
- «Управление игроками»: список записанных игроков, затем обычные кнопки участия, времени, оплаты и гостей от имени выбранного человека. Сохранение немедленное, в истории указан настоящий автор правки. В этих меню только «Назад», без «Закрыть».
- «История изменений»; внизу «Назад» / «Меню» в одном ряду. При входе из общей карточки остаётся только «Меню».

Исключение игрока с ненулевой оплатой запрещено. Сначала нужно исправить оплату
в управлении игроками. Добавление записывает участие с 0 ч; прежняя оплата сохраняется.
Список добавления содержит известных боту текущих участников этой группы, которые
ещё не играют. «Добавить через Telegram» позволяет выбрать реальный аккаунт,
включая гостя вне чата. Bot API не предоставляет полный список существующей группы.
Все списки игроков имеют страницы по восемь; карточка тренировки показывает всех.
Закрытую или отменённую тренировку перед правкой нужно открыть через изменение статуса.

## Согласованное меню и навигация

[Схемы переходов трёх ролей (.drawio)](docs/diagrams/BOT_USER_FLOWS.drawio) ·
[Интерактивный прототип](docs/prototype/README.md).

Общее меню: «🏓 Мои тренировки», «💰 Мои финансы», «➕ Создать тренировку»,
«⚙️ Настройки». Администратору доступно «📋 Управление тренировками» с выбором группы.
«Мои финансы» тоже сначала предлагает выбрать группу; финансовые операции остаются
изолированы по группам. Тексты меню и форм не содержат префикса с названием группы.

«Мои тренировки» объединяют записи пользователя из всех групп. Вверху — число записей,
сумма его наигранного времени (без времени гостей) и сумма внесённой им оплаты стола.
Статистика включает открытые, учтённые и отменённые записи, в том числе оплату без участия;
переводы между людьми в эту сумму не входят. В списке также остаются созданные пользователем
открытые тренировки, даже если он ещё не участвовал. После учёта одного авторства недостаточно.
По три кнопки на страницу, порядок — от новых по времени создания к старым.

Из списка открывается карточка просмотра с «Назад» на ту же страницу. Для открытой
тренировки есть «Открыть»; создатель и администратор группы видят «Редактировать».
Подпись о влиянии отменённой тренировки на баланс убрана. Доступ к выбранной
групповой карточке по-прежнему требует текущего членства в группе.

«⚙️ Настройки» → «Тренировка»: «Укажите параметры тренировки по умолчанию».
Кнопки «Название», «Время», затем «Назад» / «Меню» в одном ряду. Настройки принадлежат
пользователю и используются при создании в любой группе; исходные значения — «Теннис»
и 18:30. Изменения не затрагивают других пользователей и существующие тренировки.
Суперадминистратору доступно «Настройки» → «Администраторы групп» → выбор группы.

При выходе из других несохранённых форм остаётся предупреждение о сбросе ввода.
Явная «Отмена» в создании новой тренировки сбрасывает этот черновик и открывает главное меню.
В истории показываются автор, время группы и изменённые поля «до → после».
Баланс группы подписан «Имя · баланс: +300 ₽ / -300 ₽»; отдельно — «⚖️ Нулевой баланс».
При одинаковых именах используются фамилия и @username, затем проверка профиля перед выбором.

## Роли и расчёты

- Участник группы меняет только своё время, гостей и оплату стола в открытой
  или возобновлённой тренировке. Нахождение в группе не означает, что он играет.
- Создавать тренировку может любой текущий участник группы. Учесть её и применить
  правки могут её создатель или администратор именно этой группы. Снятие роли
  администратора не лишает создателя этого права, выход из группы — лишает.
  Создатель может отменять и восстанавливать свою тренировку; прав на чужие тренировки и другие группы это не даёт.
- В «Моих тренировках» авторство добавляет только открытые тренировки. После учёта авторство само по себе больше не включает тренировку в
  список: остаются обычные основания — участие, учтённое участие или оплата.
- Назначенный администратор бота управляет любыми данными тренировки,
  завершает, возобновляет, отменяет и восстанавливает её.
- Отменённую тренировку можно открыть через «Управление тренировками» и нажать
  «Изменить статус» → «Открыта». Она снова открыта: сохраняются тот же ID, игроки,
  время, оплата и история. Восстановление само по себе не меняет балансы — после
  проверки нужно выбрать «Изменить статус» → «Завершена». Реальные переводы не меняются.
- Текущие администраторы конкретной Telegram-группы имеют старшие права
  и назначают администраторов бота только для неё. Назначенный администратор
  не может выдавать права другим. Членство и старшая роль проверяются при каждом событии.
  В меню администраторов видны суперадмины Telegram и назначенные админы бота;
  остальные находятся в отдельном выборе для назначения. Назначение можно снять.
- Пользователь — реальный Telegram-аккаунт. Имя или @username не используются
  вместо Telegram ID. Администратор может выбрать реальный аккаунт через
  встроенный список Telegram, в том числе для приглашённого человека вне чата.
- Гости относятся к пригласившему: отдельных аккаунтов и самостоятельных балансов нет.
  Оплату можно сохранить после выхода из состава.
- Все суммы — целые рубли. Расходы делятся пропорционально игровому времени;
  остаток округления распределяется в стабильном порядке.
- При повторном открытии прежний расчёт сразу отменяется. Повторное завершение
  заменяет влияние именно этой тренировки одной транзакцией. Реальные переводы
  не меняются. Отмена тренировки снимает её влияние, сохраняя историю.
- «Мои финансы» → выбор группы → отправка, принятие, история и должники.
  Отправитель выбирает предложенную сумму и после реального перевода нажимает
  «Платеж отправлен». Запись получает статус «В процессе», баланс ещё не меняется.
- Только получатель через «Принять платеж» переводит запись в «Выполнен»;
  тогда проводки учитываются один раз. Администратор не подтверждает чужое получение.
- Ожидающие подтверждения суммы исключаются из новых предложений отправки.
  «Должники» показывает оставшиеся предложенные поступления с учётом этого резерва,
  а не отдельный реестр фактически учтённых балансов.
- Отправка и принятие: три записи на страницу; история и должники: пять.
  При отсутствии доступной отправки или принятия показано «Нет доступных платежей».
  Произвольная сумма, правка и отмена перевода убраны из текущего интерфейса.
  Старые учтённые переводы сохранены. [Подробности выпуска](docs/ISSUE_3_FINANCE.md).

## Таблицы базы данных

Новая схема содержит **13 таблиц приложения** в одном файле SQLite.
Идентификатор формата — `application_id = 0x54534e32`, версия — `user_version = 6`.
Версия 1 новой модели обновляется транзакционно с сохранением данных. Старая модель схемы 6 несовместима и не преобразуется автоматически.

Подробности: [все поля и связи](docs/DATABASE_V2_TABLES.md),
[обоснование модели](docs/DATABASE_V2.md), [SQL-схема](src/main/resources/db/schema.sql).

| Таблица | Что хранит | Основные связи |
| --- | --- | --- |
| `users` | Telegram-аккаунт, имя, @username и личные параметры создания тренировки | Одна запись аккаунта может быть связана с несколькими группами |
| `groups` | Chat ID, название и часовой пояс | Родитель для учёта группы |
| `group_users` | Связь аккаунта с группой, последнее известное членство, подготовленная посещаемость, будущие ручные настройки | `(group_id, user_id)` → `groups` и `users` |
| `group_admins` | Назначения администраторов бота и автор назначения | Аккаунты той же группы из `group_users` |
| `trainings` | Название, дата, начало, состояние, текущая и учтённая версии | Группа и создатель из этой группы |
| `training_players` | Участие, время, число гостей, оплата стола и порядок округления | Тренировка и аккаунт в одной группе |
| `transfers` | Стороны перевода, сумма, дата, ожидание или подтверждение получения | Обе стороны и автор из той же группы |
| `actions` | История команд и результатов, защита от повторов, необходимость обновить карточку | Группа, автор, тренировка либо перевод |
| `balance_entries` | Изменение баланса аккаунта от действия | Действие и аккаунт в одной группе |
| `bot_events` | Идентификаторы событий и отметка обработки; план только до завершения | Контекст аккаунта и группы, когда применим |
| `bot_sessions` | Выбранная группа и незавершённый ввод в диалоге | Пользователь и чат общения |
| `bot_buttons` | Непрозрачные идентификаторы кнопок и постоянных ссылок | Группа, экран и владелец личной кнопки |
| `bot_deliveries` | Результаты отправки, идентификаторы сообщений и неопределённые результаты | Чат, группа и личный получатель, когда применим |

Текущие балансы вычисляются по `balance_entries`. Общего JSON-снимка финансов
нет. JSON в журнале служит историей изменения, а в диалогах — незавершённым вводом.
Составные внешние ключи запрещают связывать финансовые записи разных групп.
Наличие строки в `group_users` само по себе не даёт доступа: человек мог выйти из чата,
но его долги и история должны сохраниться.

Посещаемость для сортировки хранится в `group_users.attendance_count` и обновляется
при изменениях тренировок. `has_played` включает подтверждённое участие в открытой
тренировке и используется для нулевых балансов. Это служебные вычисляемые поля,
в отличие от ручных настроек ниже. Порядок текущего выбора фиксируется в личной форме.
Кнопки одного экрана подготавливаются в одной транзакции; правила их срока жизни сохранены.

Версия 3 разрешает 0 ч, добавляет число гостей, состояние закрепления и состояние
открытой персональной панели. Миграция сохраняет строки, прежнее гостевое время,
историю и проводки. Старое отдельное время единственного гостя сохраняется до
следующей правки участия; новый ввод синхронизирует его со временем пригласившего.

### Поля для задуманной, но пока не реализованной функциональности

В новой таблице `group_users` уже предусмотрены:

| Поле | Назначение | По умолчанию |
| --- | --- | --- |
| `is_attending` | Ручная отметка «ходит» (1) / «не ходит» (0) в конкретной группе | `1`; не записывает человека играющим в тренировке |
| `nickname` | Имя аккаунта для отображения только в этой группе, до 64 символов | `NULL` — использовать имя из Telegram |

Редактирование этих полей, фильтрация по ним и отображение имени ещё не реализованы.
Признак «ходит» независим от членства в чате и статистики посещений. Имя не обязано
быть уникальным и не заменяет Telegram ID. Обновления из Telegram сохраняют обе ручные настройки.

## Сообщения, кнопки и повторные запросы

Общая карточка обновляется на месте. Списки и текст истории разбиваются по 8 записей;
карточка одной тренировки показывает всех участников и гостей сразу, без страниц,
в группе, личном чате и персональной панели. Это действует во всех состояниях тренировки.
Для таблицы используется расширенный формат Telegram с лимитом 32768 символов;
обычные текстовые экраны по-прежнему ограничены 4096 символами.
При нажатиях кнопок личное меню обновляется на месте. После текстового сообщения
пользователя бот отвечает новой карточкой внизу диалога; после успешной доставки
предыдущее меню удаляется. Если Telegram не разрешает удаление старого сообщения,
оно заменяется короткой пометкой без кнопок. Очередь уборки сохраняется при
перезапуске. Старые меню прежних версий, ID которых уже неизвестны, убираются
при нажатии их кнопок; бот не читает всю историю личной переписки.
Повтор обработки того же сообщения не создаёт ещё один ответ. Выбор аккаунта Telegram использует
отдельную системную клавиатуру в личном чате.

Кнопки актуального или потенциально доставленного сообщения не истекают по возрасту.
После успешной замены прежние кнопки удаляются с задержкой 2 минуты.
Постоянные ссылки, в том числе в закреплённом групповом меню, не протухают.
Одна повторно доставленная команда не меняет данные второй раз. Два настоящих
нажатия +100 ₽ увеличивают сохранённую сумму дважды. Нажатие без изменения значения
не добавляет историю. Правка от имени игрока использует те же немедленные
изменения, что и самостоятельный ввод. Поправки применяются к актуальной записи
в транзакции, без перезаписи чужого ввода устаревшим снимком.

При неизвестном результате первой отправки общая карточка не публикуется повторно
автоматически. Администратору доступно восстановление сообщения с предупреждением
о возможной старой копии. После неопределённой первой отправки личного меню
его можно восстановить командой `/start`.

## Запуск и проверки

Нужна Java 21. Обёртка Gradle включена в репозиторий; скрипт умеет находить JDK
из IntelliJ IDEA на macOS. Токен хранить только в локальном `.env`:

```sh
cp .env.example .env
./scripts/gradle.sh test installDist --no-daemon
./scripts/gradle.sh run --args='bot' --no-daemon
```

В `.env` заполнить `TELEGRAM_BOT_TOKEN`. Новый путь по умолчанию —
`data/settlements.sqlite`. Не запускать одновременно локальный и серверный
процессы с одним токеном.

Проверки покрывают пропорциональный расчёт и округление, изоляцию групп и ролей,
параллельные поправки, повторные события, завершение и отмену, реальные переводы,
устаревшие формы, отзыв доступа, кнопки и сбои отправки, длинные списки и поля Telegram.

Демонстрация в **новом отдельном файле**, без обращения к Telegram:

```sh
./scripts/gradle.sh run --args='demo data/demo-new.sqlite' --no-daemon
./scripts/gradle.sh run --args='verify data/demo-new.sqlite' --no-daemon
./scripts/gradle.sh run --args='backup data/demo-new.sqlite data/demo-copy.sqlite' --no-daemon
```

Демонстрация создаёт искусственные аккаунты только в указанном тестовом файле.
Рабочий интерфейс получает аккаунты из Telegram. Для просмотра базы:
[инструкция](docs/DATABASE_INSPECTION.md), [примеры запросов](docs/inspect.sql).

## Рост базы и резервные копии

[Ревью хранения и измеренный прогноз](docs/STORAGE_REVIEW.md): для 40 человек,
10 играющих и 156 тренировок в год новая модель немедленного сохранения дала
14,59 МиБ; практический запас — 20–25 МиБ плюс исходные данные. Согласованная очистка завершённых служебных планов
сохраняет идентификаторы событий и всю финансовую историю. Файл существующей базы
не обязан сразу уменьшаться: освободившиеся страницы используются повторно.

[Способы и согласованная схема резервного копирования](docs/BACKUPS.md).
Пошаговая подготовка и обучение: [практический курс](docs/backup-course/README.md).
Локальные команды backup/verify открывают источник только для чтения, без миграции;
копия создаётся через SQLite Online Backup API, проверяется и получает права 0600.
Плановое резервирование и внешний архив пока не настроены. Состояние каждого
выпуска и результаты проверки установленной версии — в DEPLOYMENT_STATUS.md.

Статусы тренировок: OPEN («Открыта»), CLOSED («Учтена»), CANCELLED («Отменена»).
При переходе CLOSED → OPEN отменяется только расчёт этой тренировки, сбрасываются
учтённая версия и отметки учтённого участия. Введённые время и оплата сохраняются.
Схема 5 переводит прежние REVIEW в OPEN с отдельной компенсирующей записью; история
и переводы не удаляются. REVIEW у переводов теперь означает ожидание подтверждения получателем; код состояния сохранён.

Личные настройки хранятся в `users.training_title` и `users.training_time`.
Схема 6 удаляет групповое `groups.default_start_time`. Для глобальных кнопок
`bot_buttons.group_id` допускает NULL; групповые связи по-прежнему проверяются внешними ключами.
Черновики создания сохраняют введённые данные и переходят к выбору группы в конце.
Финансовые записи при этом обновлении не меняются.

## Границы кода после рефакторинга интерфейса

- `selfservice/ScreenLayout.kt` строит кнопки и сохраняет их в одной партии;
  `TrainingScreens.kt` отображает карточки, редактор и участие. `Screens.kt`
  отвечает за остальные меню и формы, `TrainingCard.kt` — за таблицу.
- `application/TrainingLifecycle.kt` задаёт допустимые переходы статуса одновременно
  для кнопок и исполнения команд. `AttendanceRules.kt` вычисляет изменение участия
  без обращения к Telegram или базе. `SettlementService` проверяет права и сохраняет
  запись, историю и проводки в одной транзакции.
- `storage/Database.kt` управляет соединениями, транзакциями, проверкой и резервным
  копированием. `SchemaMigrations.kt` и `TrainingStateMigration.kt` обновляют схему;
  `TrainingRepository.kt` читает тренировки без зависимости от сервиса;
  `Sql.kt` содержит параметризованные запросы и последовательное чтение больших выборок.

Схема остаётся с 13 таблицами. Сам рефакторинг не создаёт новых данных и не меняет
расчёт. Общая статистика и суммы проводок читаются последовательно, без временного
списка на каждую строку истории; точность сумм и контроль переполнения сохранены.

[Анализ задержек интерфейса](docs/UI_PERFORMANCE.md): измерения чтений базы, запросов Telegram и ограничения проверки.

[ERD базы в draw.io](docs/diagrams/DATABASE_ERD.drawio) — пять вкладок: обзор, аккаунты и группы, тренировки, финансы, состояние бота. Показаны 13 таблиц, 103 поля и 33 внешних ключа текущей схемы.

### Дизайн на согласовании

[Произвольные платежи и административная запись](docs/prototype/FINANCE_PROPOSAL.md)
подготовлены как отдельный интерактивный макет. Новые финансовые маршруты пока
