# Безопасность публичной документации

Код, схема базы, инструкции развёртывания и результаты искусственных тестов публичны.
Настройки рабочего экземпляра, данные участников и эксплуатационные заметки — нет.

## Что не включать в Git

- Токены Telegram, пароли, приватные ключи и файлы реальных настроек.
- Базы данных, их копии, выгрузки, журналы сообщений и реальные ID пользователей/чатов.
- Адреса серверов, личные пути, сведения о сторонних службах, рабочие ссылки на бота.
- Снимки экрана и отчёты, позволяющие восстановить эти сведения.

.gitignore исключает .env, bot.env и каталог data. Это защита от случайного
добавления, а не проверка содержимого: секрет можно случайно вставить и в README.
Перед публикацией просматривать diff и проверять историю при обнаружении утечки.
В примерах использовать вымышленные данные и явные обозначения для подстановки.

## Если сведения уже опубликованы

1. Настоящий секрет сначала отозвать и заменить у поставщика.
2. Удалить сведения из файлов и всех публикуемых веток и тегов, переписав историю.
3. Проверить pull request, форки, выпуски, артефакты и старые ссылки на коммиты.
4. При необходимости обратиться в поддержку GitHub для удаления удерживаемых
   копий. Скачанные кем-то копии репозитория принудительно отозвать невозможно.

После переписывания истории использовать свежий клон; не сливать старые ветки,
иначе удалённые сведения могут вернуться. Резервную копию прежней истории хранить
закрыто вне публикуемых ссылок Git.

[Инструкция GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
